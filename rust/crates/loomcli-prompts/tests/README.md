# Reference test map

The TypeScript reference's tests are the behavioral oracle. Each row names one file under `typescript/packages/prompts/tests` and its status: ported (with the Rust test file and the case count, a `test.each` row counting as one case), partly ported (with what remains and why), or not applicable (with the reason). Behavior tests drive an application through `Application::run` or `invoke` on a mock process and assert the answer, the exit code, and the bytes or the screen stderr shows. `support/mod.rs` holds the shared helpers, and `support/screen.rs` is core's headless screen, copied, which stands for the reference's terminal emulator replay.

| Reference test file | Status |
| --- | --- |
| `choices.test.ts` | Ported: `choices.rs`, every case (27). The linked multiselect whose input's validator answers numbers asks with `multiselect_as`. |
| `editing.test.ts` | Partly ported: `editing.rs` (75 of 77). Not ported: "an accepted secret discards a paste started in its Enter read and completed during validation" and the "during an async validator" row of "a held ESC older than the window": both need an asynchronous validator, and Rust validators are synchronous (see the Prompts rows of `docs/deviations.md`). The held-Escape rows read the reader's clock under paused Tokio time, as the reference fakes `performance`. |
| `editor.test.ts` | Ported: `editor.rs`, every case (37). A child that never exits is a script that waits on its `ProgramCall::signal`. |
| `editor-views.test.ts` | Ported: `editor.rs`, every case (15). |
| `fitting.test.ts` | Ported: `fitting.rs`, every case (37). |
| `interactive.test.ts` | Ported: `interactive.rs`, every case (30). The reference drives a fixture on a real pseudo-terminal through `zpty`; the port types the same keys on the mock keyboard into the same fixture scenarios and reads the same answers and lines. The configuration-file case installs a fixture plugin whose core `ConfigurationSource` answers the port's raw `"006050"`, standing for the reference's settings file and `--config`. |
| `line-questions.test.ts` | Ported in `line_questions.rs` and `editor.rs`. Typed answers, secret raw mode, confirms, select and multiselect numbers and defaults, search and linked validation, editor frames, input-region turns, control keys, and the environment and flag cases use the mock keyboard or editor. The flag fixture declares the plain mark directly. |
| `list-frames.test.ts` | Ported: `list_frames.rs`, every case (16). |
| `lists.test.ts` | Partly ported: `lists.rs` (28 of 29). Not ported: "a first call aborted while its prefill resolves draws no settled frame", which places a key between a settling call's awaits by JavaScript microtask order; the Rust question settles a call without yielding to a key, so the window the case closes does not exist. The stale-call case covers the rule that a stale call never replaces its list. The `null` and `undefined` value cases read `Option` values. |
| `live.test.ts` | Partly ported: `live.rs` (4 of 23, plus two Rust-only cases). Ported: each kind asks in an input region (its answers, its hold and release controls, and the cursor each question hides after its first frame; the reference also records every `out.draw` and `out.region` call, which a Rust test cannot intercept), a lane message written while a question asks, a question whose region a failure closes while the question still reads (the question runs on its own task, as the reference's sibling promise keeps running, and the screen is asserted exactly), and two questions asked at once. Rust-only: a question dropped for a timeout closes its region so the next one asks, and a question dropped while it waits for its turn draws nothing. Not ported: the twelve edge cases that resize the terminal between frames (narrowing, widening, a full line, a wide glyph at the edge), which replay resizes through a reflowing emulator and prove core's region redraw, which core's own live-region tests own; and the seven "a real terminal" cases, which drive a real pseudo-terminal. |
| `link-arity.test.ts` | Ported in `questions.rs`. Text, select, and multiselect refuse to link arity options. A one-word option can still link when its validator outputs a pair. |
| `mcp.test.ts` | Not applicable here: it launches the MCP server of a fixture process. An MCP tool call is an invocation by name, whose question rules `questions.rs` ports through `invoke` (supplied, missing, and unlinked). |
| `message-voice.test.ts` | The progress log's singular and plural dropped-lines sentences are checked as exact stderr bytes in `progress_log.rs`. The reference's source-file message-voice checks have no Rust counterpart. |
| `plain-pty.test.ts` | Real terminal case awaits LM-622's CI pseudo-terminal driver. Mock keyboard, editor, and progress cases cover the plain output and answer behavior in `line_questions.rs`, `editor.rs`, and `progress.rs`. |
| `plain-signals-pty.test.ts` | Real terminal cases await LM-622's CI pseudo-terminal driver. `line_questions.rs` checks interrupt and suspend behavior, raw mode restoration, and the bytes on the mock terminal. |
| `progress.test.ts` | Ported in `progress.rs`. Shared scenarios cover live and plain output, every end and repeat end, view overrides, compat glyphs, a terminal lend, quiet and plain switches, and invocation messages and events. The SIGINT case raises the signal on the mock and checks the exit code, cancelled frame, and re-raised signal. Core's `shutdown_process.rs` covers the operating system's signal exit. |
| `progress-estimate.test.ts` | Ported in `progress_estimate.rs` under paused Tokio time. The worked sequence asserts every report frame in order. Timer frames, sample rules, view data, narrow columns, formatting, and plain output use the same counts and times as the reference. The unit case in `src/estimate.rs` checks bounded retention at the reference's reporting volume. A deque evicts old samples as the anchor moves, so the reference's batch eviction count has no Rust counterpart. |
| `progress-log.test.ts` | Ported in `progress_log.rs`. The mock exercises text and streamed chunks, limits, parsing, clipping, live frames, retained output and lanes, and output order across concurrent ends. The line limit is checked across chunks, at the exact bound, and with astral characters. Child output tests cover split UTF-8 scalars and literal markup delimiters. Rust string chunks are complete Unicode scalars. |
| `progress-log-height.test.ts` | Partly ported in `progress_log_height.rs`, `progress_tasks.rs`, and the share table in `src/height.rs`. The mock exercises layout, resize, opening and closing lines, the action and middleware's shared run, separate runs, view overrides, and the independence of fitted rows and retained output. Growing logs and finished rows after a shrink respect the rows another tree last drew. Zero rows stand for an unknown height. The hand-built context without a host and the configuration source's context have no Rust counterpart. Rust seals `ProgressContext` to action and middleware contexts. |
| `progress-tasks.test.ts` | Ported in `progress_tasks.rs`. Tests group related reference rows for nested tasks, end states, collapse and retention, logs and height, plain lanes, event order, overrides, and narrow or multiline labels. Sibling cases distinguish explicit and core close order. Four-worker tests race child opens and ends against a root end, action failure, and cancellation. A signal raised by a progress observer also preserves the close order. Redraw tests cover a delayed view and an exhausted Tokio task budget. |
| `progress-pty.test.ts` | Partly ported through `progress.rs`. The real terminal replay for clear, skipped dimming, and warning glyph color awaits LM-622. |
| `progress-estimate-pty.test.ts` | Partly ported through `progress_estimate.rs`. The real terminal replay for the dim estimate and its removal on an end line awaits LM-622. |
| `progress-log-pty.test.ts` | Partly ported through `progress_log.rs` and `progress_log_height.rs`. The real terminal replay for dim rows, success removal, failure retention, and two logs sharing a 10-row terminal without stale scrollback awaits LM-622. |
| `progress-tasks-pty.test.ts` | Partly ported through `progress_tasks.rs`. The real terminal replay for indent, collapse without a blank row, and the kept failed tree awaits LM-622. |
| `questions.test.ts` | Ported: `questions.rs`, every case (28). The embedding host is a `process_handle` with a scripted stdin. The abort case does not read raw mode at the instant of the caller's abort: a caller's token reaches the run where core polls it, and the case asserts the terminal is cooked when the run resolves. |
| `signals.test.ts` | Not applicable: every case runs a real process under `zsh` job control (SIGINT ending a shell loop, Ctrl-Z and `fg`, a process that exits mid-question or mid-editor). The mock-process cases cover the same rules: Ctrl-C and Ctrl-\ at each kind (`interactive.rs`, `questions.rs`), Ctrl-Z's bracketed paste and its resume (`editing.rs`), a suspend while the editor runs (`editor.rs`), and a shutdown that cuts the run off while the editor runs (`editor.rs`). |
| `viewport.test.ts` | Ported: `viewport.rs`, every case (10). The rows a frame moves down are counted by drawing each recorded frame again once the question answered. |
| `support.ts`, `terminal.ts` | Helpers, not tests. |
