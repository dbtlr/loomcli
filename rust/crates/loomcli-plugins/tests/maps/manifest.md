# Test map: the manifest plugin

The plugin is `manifest` (`--manifest`) with its collecting extension `@loomcli/plugins/manifest/command`. Reference tests live in `typescript/packages/plugins/tests`. The Rust tests are `tests/manifest_*.rs`, run with `cargo test -p loomcli-plugins --no-default-features --features manifest`. Their fixture application installs the manifest plugin alone (plus a small plugin standing in for help's `manifest/command` values), so its globals are the fixture's own option and `--manifest`; the `--help`, `--version`, and `--format` rows and the takeover order against them belong to those plugins' packages.

| Reference file | Status | Notes |
| --- | --- | --- |
| `passthrough-mode.test.ts`, `manifest.test.ts` | ported, parsing and terminal cases | `passthrough_mode.rs` checks both declaration facts. `manifest_document.rs` pins the key order and rejects an extra manifest spelling after the delimiter. |
| `manifest.test.ts` | partly ported, 24 cases in `manifest_document.rs` and 1 in `format_fields.rs` | The formatter projection test checks the result and both control options, including the `--format` enum and the exact `--fields` entry. Ported: the pinned `get` slice byte for byte, the envelope key order and `configuration: null`, `-M` through `short('M')` and no short by default, the short collisions with a global, a local, and a plugin option (3 owners as one case), the root slice with its visible children and the hidden one omitted, a result's `kind`/`views`/`default`/`mediaTypes` and the encodings from media types (the `wired` fixture, with core views in place of the formatter's), deprecated and empty Commands, line breaks read as one space, hidden Command slice and group slice, C1 escapes and the raw U+00A0, argument entries, `stdin` and content entries with their key order, an unknown Command's routing error, a `--manifest` after `--`, bytes unchanged under forced color, the application with no description, and option groups that would reveal a hidden member. Ported from a core-only fixture plugin: the `configured` scenario (a source's schema as `{ schema }` in key position) and an earlier-installed takeover winning over `--manifest`; the unknown-command case asserts the exact stderr. Added: schema numbers written as `JSON.stringify` writes them, a non-letter short setting panicking at the call, either case of an ASCII letter as the short setting. Not ported: the formatter's `--format` option entry and the agent-shaped run (they need the format plugin; the formatter package covers `--format`), the `--help --manifest` and `--version --manifest` precedence and the help-page `--manifest` row (help and version packages), the packed consumers (npm packaging, no Rust counterpart). Not applicable: the unencodable default and schema scenarios (`bigint`, `nan`, `function`, `infinity`, `date`, `map`, `array-date`, `deep-bigint`, `global-nan`, `child-nan`, `argument-nan`, `schema`, `schema-cycle`, `configuration-nan`) because a `serde_json::Value` cannot hold them, and `null-prototype`, which has no Rust form (see deviations). |
| `manifest-failures.test.ts` | ported, 13 cases in `manifest_failures.rs`; 9 rule cases in `manifest_extension.rs` | Ported: the exit-code table in ascending order with failures in depth-first order, every slice carrying the whole table and a hidden Command joining it, `[]` for no declared failures, author and plugin values concatenated with an identical pair once, the `code`/`exitCode`/`meaning` key order, one code on two Commands listed on both, classes that inherit `1` and `fatal` or declare `2` adding no row, the two-exit-codes and two-meanings conflicts (root and routed slices, in a development and a distributed build), a meaning quoted with controls escaped, the same-Command conflicts, and no conflict without `--manifest`. Rule cases in `manifest_extension.rs`: a meaning, an example command or note on two lines, and blank details rejected at the call (a lone U+0085 is content, U+FEFF is not); valid values pass; a declared failure stores its class's code, exit code, and meaning; an inheriting class stores `fatal` and `1`. `failure-bad-code` is ported (a hand-written code outside the grammar, plus the exit-code bound). Not applicable: `failure-function`, `failure-foreign-class`, `failure-missing`, and `failure-stale-name`, because a declared failure is a `DeclaredFailure` value, not a class passed as free input. The conflict tests compare the whole development report and the distributed message. |
| `extension-facts.test.ts` | partly ported, the manifest case in `manifest_extension.rs` | Ported: the manifest facts keep every field (details, examples, failures) and read each failure from its class. The help, MCP, and configuration cases belong to those packages. |
| `help-manifest.test.ts` | not applicable here | Belongs to the help package. |
