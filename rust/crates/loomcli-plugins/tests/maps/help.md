# Test map: the help plugin and the help page

The plugin is `help()` (`-h`, `--help`, the optional `help` Command, paging), its descriptors in `help::extension`, and the declared `help::views::help_page()` view. Reference tests live in `typescript/packages/plugins/tests`. The Rust tests are `tests/help_*.rs`, with shared fixtures in `tests/help_support/`, run with `cargo test -p loomcli-plugins --no-default-features --features help`; one unit test sits in `src/help/details.rs`. One case of `help_hint.rs` installs the suggestions plugin and runs only under `--features "help suggestions"`.

The reference's fixtures install `version()`, `verbose()`, `manifest()`, and other plugins beside `help()`. The help page reads the graph alone, so the Rust fixtures stand those plugins in with plugins that declare the same options and Commands (`version_stand_in`, `verbose_stand_in`, and the stand-ins in `help_conformance.rs`), and install the Loom palette and the custom themes through core's theme slot. The pages they print are the reference's bytes.

Added beyond the reference: `help_conformance.rs` compares 21 help cases with the shared expectations outside listed differences: jsonkit's root (both variants), `get`, `select`, `fetch`, `stats depth`, and `stats depth max` pages, its help Command pages and unknown-word failures, and textstat's pages, from applications shaped like the examples. `help_manifest.rs` also checks that one list of `CommandExample` values serves both `HelpCommandFacts::examples` and `ManifestCommandFacts::examples`: as in the reference's `command-example.ts`, `help::extension::CommandExample` is the manifest's type, re-exported, so the `help-extension` feature turns on `manifest-extension`.
