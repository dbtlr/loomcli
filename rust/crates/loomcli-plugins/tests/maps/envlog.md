# Test map: the dotenv and logging plugins

Reference tests live in `typescript/packages/plugins/tests`. The Rust tests are `tests/dotenv_plugin.rs`, `tests/logging_records.rs`, `tests/logging_rotation.rs`, and `tests/logging_failures.rs` (with the fixture in `tests/logging_support/`), plus the unit tests in `src/logging/file.rs`. Run them with `cargo test -p loomcli-plugins --no-default-features --features "dotenv logging"`. Every case runs through `Application::run` (or `invoke`) on the mock process with a temporary directory.

| Reference file | Status | Notes |
| --- | --- | --- |
| `dotenv.test.ts` | partly ported, 43 Rust tests (the table-driven cases loop over every reference row) | `dotenv_plugin.rs`: settings (no settings, `except`, warning only for an imported name, `only` with an env-bound option), empty values and `env_allow_empty`, an invalid imported value naming its variable, physical warning lines, the named run's captured warnings, each malformed form, a malformed duplicate, silent files and directories, the unreadable file (a self-referencing link), every value form of the parse table, the multi-line private key, the unterminated quote, non-LF separators, every layered-file precedence and mode case (including `test` and a mode that names `.env.local`), warning order, lists across layers, the 27 reference expansion rows plus 4 added, environment-first reads, a reference reading a name an allow list excludes, and the any-hash rows. Also ported: output capability detection (`FORCE_COLOR` from `.env` styles stdout), publication (a recording handle sees one `publish_env` per accepted addition on an argv run and none on `invoke`), and the Bun-parity file set with the plugin's own expected values (no Bun binary, so the native half is not compared). Added: invalid listed names panic with the whole diagnostic compared exactly, and a listed name twice is accepted. Not ported: "valid names that also name object properties reach the process" (a map has no object properties), "a reference reads past a name the environment holds as undefined" (`Env` has no undefined value), the `__proto__` snapshot case (no object prototype in a map; the `constructor` name is just a name). |
| `logging.test.ts` | partly ported, 34 Rust tests | Lines are pinned in the raw text and compared as bytes. `logging_records.rs` (19): the three default levels, all five at `trace`, the key order with `failure` and with `defect`, the record in the file when the call returns, `file` as a name, relative, absolute, and `~/` (also with repeated slashes), a record with non-ASCII, escapes, and a float written byte for byte, the darwin row, `XDG_STATE_HOME` unset and relative, the console bytes equal to the file's, no file under the console, and the invocation by name with the console, the captured env, and the replaced env. `logging_rotation.rs` (7): `maxBytes` 200 with `keep` 2, `keep` 0, a name with no extension, an oversize record in a new file, an oversize record in a missing file, and the two-writer cases on threads. `logging_failures.rs` (8): append failures, create-directory failures, an unset `HOME`, a relative `HOME` for the default and `~/`, a failed rotation that still writes, no `on_error`, a later record after healing, and an `on_error` that fails as `foreign-throw` with exit 1. Added: `LogLevel::Fatal` writes fatal events alone. Not ported: the real-process `process.exit()` case (a synchronous-write check replaces it), the two real-process concurrency cases (threads replace them; see the deviation), and packaging (`check:packed` is a Node and Bun check). |

Added: copy naming for an extension, none, several dots, and a leading dot. |
