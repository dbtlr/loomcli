# Test map: the service plugin

Reference tests live in `typescript/packages/plugins/tests`. The Rust tests drive the plugin through its public surface (`service()`, `Service::probe`, and the Commands it contributes) on the mock process, in a temporary sandbox of a home, a configuration folder, a state folder, and a working directory under the system's temporary folder. They assert exact stdout, stderr, files, modes, record bytes, and exit codes. `tests/service_support/mod.rs` is the port of `fixtures/service-run-app.ts`, `service-programs.ts`, `service-graph.ts`, and the sandbox of `service.test.ts`: the application `notes`, and a `systemctl`, `loginctl`, and `launchctl` that answer from a scenario's rules (taken in turn, the last repeating, a call no rule names exiting 0 with `manager output`) and record each call with the `XDG_RUNTIME_DIR` it saw. `tests/service_support/deaf.rs` wraps the mock process so one call's child ignores `SIGTERM` and only `SIGKILL` ends it.

| Reference file | Status | Notes |
| --- | --- | --- |
| `passthrough-mode.test.ts`, `service.test.ts` | ported, parsing and terminal cases | `passthrough_mode.rs` checks run words with and without the mode, and a root with both arguments and child Commands. |
| `service.test.ts` | ported, 76 of 76 | `service_install.rs` (installing 9: the linux and darwin sequences, the pinned quoting, the earlier unit after a label change on both backends, the install that failed between its write and `bootstrap`, no description, two line breaks), `service_umask.rs` (the umask 002 row, in a process of its own because the umask is process-wide), `service_refuse.rs` (refusing 16: the two builds, the three occupants and the changed and rendered-text files on both platforms, win32 and a relative HOME for every child, a newline in the program, a damaged and an unknown-format record), `service_children.rs` (children 11 and managers 7), `service_status.rs` (status 13), `service_waiting.rs` (waiting 7), and `service_graph.rs` (settings and the graph 12). `it.each` rows count one each and run as one test over their rows. |
| `service-parts.test.ts` | ported, 9 of 9 | `src/service/tests.rs` reads the private pieces: systemd quoting, the plist's entities, the `show` and `print` readers (7 and 4 rows), the text view's whole path, padding, and escaping, and the status members' order. The label grammar's 12 rows are in `service_graph.rs`, which reads them as the panic at the `service()` call. The control character function's 7 rows are read as behavior in `service_refuse.rs`: a description holding U+0000, U+001F, U+007F, or U+009F is refused, and U+00A0, U+2028, U+0085, and a space install. |
| `service-reads.test.ts` | ported, 9 of 9, through the Commands | The reference calls `readCall` with a fake manager; the Rust read is private, so the cases run through `status`. The 5-second limit, the `SIGKILL` at the limit, and a child that ignores `SIGTERM`: `service_waiting.rs` (a state read that never exits, one that ignores `SIGTERM` through `deaf`, the elapsed time at least 5 seconds). A read that exits 143 or 137 on its own reads as an exit, not as one that ran out: `service_status.rs`. A run cancelled during a read returns the cancellation with no note, and a shutdown during a read that ignores `SIGTERM` kills it with `SIGKILL` before the limit: `service_waiting.rs`. A program that cannot start: `service_status.rs` and `service_children.rs`. The reference's "leaves no timer running" and "the handler is removed after" have no observable form in Rust: the timer is a value dropped with the read, and the registration is removed by the read. |

Added beyond the reference: the `--format json` and `--format jsonl` bytes of `status` when the `format` feature is on (`the_installed_formatter_selects_json_and_jsonl_for_status`); the JSON bytes of `status` otherwise come from `Application::invoke` with the view named `json`, so the acceptance run of the `service` feature alone covers them. The reference's `check:packed` packaging step has no counterpart.
