# Test map

Each row is one file of `typescript/packages/validators/tests`. A count is the number of Rust `#[test]` functions that carry the file's cases; a function walks a table, so the reference's table rows are ported row for row with the same tokens and the same expected sentences, values, schemas, and fault text. Messages and published schemas are compared as text. A published schema is compared without its `$schema` member, which core serves, in the reference's key order.

A fault at a factory call is a panic at the author's line that carries the Developer Diagnostic (see `docs/deviations.md`, Validators). Its test reads the rule identity, the sentence, and the correction, and checks the finding that rebuilds the call and marks the argument.

| Reference file | Status | Rust file and what differs |
| --- | --- | --- |
| `support.ts` | not applicable | Helpers. `tests/support/mod.rs` is the Rust form: a context over the mock process, verdict and rejection readers, a small JSON Schema checker for the soundness tables (`type`, bounds, `enum`, `pattern`, `anyOf`, and the formats a plain parse can check), and fault capture. |
| `catalog.test.ts` | partly ported, 3 tests in `catalog.rs`, 1 in `fault.rs` | Ported: all 18 factories publish a schema that opens with its type, the published key order, and a validator that holds no state. Not applicable: the export-name list and the Standard Schema `vendor` and `jsonSchema` converter checks (the Rust crate root and `Validator` trait replace them). The Ajv soundness tables run in each factory's file through the small checker; `format` is checked for `ipv4`, `ipv6`, `uuid`, `date`, `hostname`, and `uri` only. |
| `catalog-diagnostics.test.ts` | partly ported, 5 tests in `diagnostics.rs` | 27 of the reference's 29 fault scenarios, with Rust spellings, the 8 marked findings rebuilt as setter calls, and the set of rules. `text-pattern` is the regex-crate fault in place of the flag fault, and `issue-parameters` is raised by a code's check. Not applicable: `context-outside-run` (a Rust validator always receives its context) and `issue-code-name` (a bad code is a compile error in a constant). |
| `catalog-run.test.ts` | ported, 8 tests in `catalog_run.rs` | The inspected graph reads each published schema, the action receives the byte count, the canonical address, the pairs in order, and the layout outputs, defaults pass the validator, and a rejection reads its catalog sentence. The `--manifest` document belongs to the plugins package; the graph is what it reads. |
| `codes.test.ts` | ported, 15 tests in `issue_codes.rs` and 3 in `failure_view.rs` | All 51 codes: the issue each configuration earns, its parameters and sentence, and that every other code reads `None`; the strict parameter shapes of `read` (an array reads `None`); whole-number parameters as digits up to 2^64; the bytes and time printers; the key-value and path sentences; and the `InputError` override that rewords `integer-range` through a run. Not applicable: type-level `expectTypeOf` checks. |
| `create.test.ts` | partly ported, 6 tests in `custom_pipe.rs` | Parse decides the verdict, an issue passes through unchanged, the output is the parse value, the input schema is published or `None`, the context reaches `parse`, and `$schema` in the schema is a fault. Not applicable: promises, the `~standard` protocol, the draft target, the output schema, and the context-outside-a-run sentence. |
| `issue-code.test.ts` | partly ported, 5 tests in `custom_pipe.rs` | Building and reading an issue, a copied issue read back, the `None` cases, the grammar of a code, and the parameter check. Not applicable: schema libraries and a schema that throws or answers asynchronously (a code has typed parameters). A code outside the grammar panics in `issue_code` (a compile error in a constant). |
| `pipe.test.ts` | partly ported, 7 tests in `custom_pipe.rs` and 2 in `catalog_run.rs` | An omission-aware first beside `validate_omitted` (the `greet` case: stdout `hello FALLBACK\n`, exit 0). The step reads first's value, first's rejection ends the pipe, steps run in order, issues pass through unchanged, a step receives the context, the pipe publishes first's schema (or none), nesting, a chain of eight steps, and a multiple option checks each value. Not applicable: the sync-or-promise answer, schema-library stages, realms, the types, and the output side of the converter. |
| `text.test.ts` | ported, 10 tests in `text.rs` | `text({ minLength: 0 })` is `text().min_length(0)`, which comes before a `max_length(0)` because each setter judges the bounds at its call. Not applicable: a negative or fractional length (a `usize`), the JavaScript regular-expression flags, and the type that pairs a pattern with its message. A pattern the `regex` crate cannot compile, and an empty message, are the added faults, as is regex-only syntax such as `(?i)`; `\d`, `\w`, and `.` match as ECMAScript matches. |
| `numbers.test.ts` | ported, 12 tests in `numbers.rs` (with `one-of.test.ts`) | Every accepted and rejected token of `integer`, `number`, and `port`, the schemas, and the bound faults. An infinite `integer` bound is not applicable (an `i64`). |
| `one-of.test.ts` | ported, in `numbers.rs` | Accepted and rejected tokens, the enum schema, the value listed twice, and the added empty list. The output-type check is not applicable. |
| `url.test.ts` | ported, in `url_uuid_date.rs` (7 tests with `uuid-date.test.ts`) | Every accepted token and its `href`, every rejected token and its sentence, the schemas, and the protocol faults. |
| `uuid-date.test.ts` | ported, in `url_uuid_date.rs` | Every `uuid` and `date` token and the schemas. |
| `date-time.test.ts` | ported, 10 tests in `date_time.rs`; the run case in `catalog_run.rs` | Offsets, rejected tokens, pinned and host zones, gaps and overlaps, the schema, and the zone fault. Added: an instant after 9999-12-30T22:00:00Z is rejected (a recorded deviation). Not applicable: reading the host zone outside a run. |
| `time.test.ts` | ported, 13 tests in `time_of_day.rs` | The default grammar, bounds, layouts, forms, and schemas. |
| `layouts.test.ts` | ported, 16 tests in `layouts.rs` | Every layout reading, rejection with every form, forms written once, the published patterns, the escaped literals, the zone cases, and every layout fault. |
| `duration.test.ts` | ported, 7 tests in `duration.rs` | The grammar, systemd spellings, the capital `M`, rejected tokens, bounds, and the schema. |
| `bytes.test.ts` | ported, 6 tests in `bytes.rs` | The grammar and units, whitespace, rejected tokens, bounds and their printing, and the schema. |

| `key-value-email.test.ts` | ported, 8 tests in `key_value_email.rs` | Splitting, every separator, rejection, the schema per separator, the separator faults, and `email`. |

| `probe.test.ts` | not applicable | Every probe failure rejects the token (a recorded deviation), so there is no class of failure that throws. The `ENOENT`, `ENOTDIR`, `EACCES`, and `ELOOP` verdicts and a name too long run in `path.rs`. |
