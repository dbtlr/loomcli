# ADR-0160 - A Command with an action may declare arguments and hold children, and an exact child name routes first

## Context

[ADR-0004](0004-arguments-and-children-are-exclusive.md) makes a Command declare arguments or attach children, never both, the unnamed root included. Its reason is that a bare word under such a Command is either a route or an argument, so allowing both forces the router to guess, and the guess changes when a child is added later.

That rule costs more than it saves now that most of Loom's projections are plugin Commands. A root that declares arguments, the shape of `ripgrep`, `cat`, or the textstat example, cannot install the completion, man page, MCP, skills, self-update, or service plugin, because each one contributes Commands under the root. The only fix today is to move the root's arguments into a child Command, which changes how every operator runs the application. The LM-362 floor survey ranked this among the three largest gaps: Cobra, clap, and Crust all allow the shape, and clap needs `args_conflicts_with_subcommands` to forbid it.

[ADR-0159](0159-passthrough-is-a-mode-a-command-declares-and-required-arguments-may-follow-a-variadic.md) gives the shape its escape. Without the passthrough mode, every word after the first bare `--` fills the routed Command's arguments, so `textstat -- completion` can count a file named `completion` once the root may hold a `completion` child.

The owner settled the shape in grooming (LM-403): the shape is always allowed, with no opt-in call; a word that names no child fills the arguments with no diagnostic about a near-miss of a child's name; help and the missing-subcommand failure say how to pass a child's name as an argument; and `locate()`'s `command` position gains a field rather than a new kind.

## Decision

- **The shape.** A Command with an action, the root included, may declare arguments and hold children, in either order, with no opt-in call. `argument()` no longer removes `command()` from the value it returns, and `command()` no longer removes `argument()`. A plugin's Commands join a root that declares arguments like any other children.
- **A group declares no arguments.** A Command with children and no action is a group, and a group's arguments reach no action, so a group that declares an argument is [`@loomcli/core/command-without-action`](../core/diagnostics.md#loomclicorecommand-without-action), as a group that declares `.stdin()` or the passthrough mode is: at attach, and for the root at build. Its sentence is `Command "cache" declares arguments but registers no action to receive them.`, and its correction is `Declare the arguments on the Command that reads them, or register an action.` The rule `@loomcli/core/arguments-beside-children` is retired.
- **Routing.** At a Command with children, a plain word that is exactly a child's canonical name or one of its aliases descends into that child, as today. A plain word that names no child ends routing:
  - on a Command that declares at least one argument, the word is the Command's first argument, and its action runs with it;
  - on any other Command with children, it is the unknown-command error that lists the children's canonical names, as today.
- **Routing ends at the first argument.** Once a word fills an argument, no later word names a child, so `textstat a.txt completion` counts two files. This is the existing rule of the routed Command's words: a later plain word is an argument even when it matches a child's name.
- **A parent's own options.** Routing reads the own options of a Command with children as [ADR-0152](0152-routing-reads-a-groups-own-options-as-it-reads-a-parents-own-options.md) and [ADR-0055](0055-an-invocation-routes-on-global-options-then-parses-the-routed-commands-words-against-one-table.md) state, so an option's declaration still says whether the next word is its value. A plain word after one is that option's value, a child's name, or, on a Command that declares arguments, its first argument, in that order, and an own option read before that word binds to the Command routing finally reaches: `textstat --total a.txt` binds `--total` to the root, and `textstat --total completion install` binds it to `install` under ADR-0152's rules.
- **The `--` escape.** Routing ends at the first bare `--` in both modes, under ADR-0159. On a Command without the passthrough mode, every word after it is a plain word that fills the Command's arguments, so `textstat -- completion` fills `files` with `completion`. On a Command with the passthrough mode, those words reach `passthrough`, so a child's name can only be an argument there through its position after another argument.
- **No near-miss diagnostic.** A plain word that names no child fills the arguments even when it is close to a child's name, as in Cobra and clap. The action alone knows what an argument means, and a file named `complte` is a legitimate argument.
- **The missing-subcommand failure.** When routing reaches a group through one word from a parent that declares at least one argument and does not declare the passthrough mode, the word could also have been meant as the parent's argument. On an argv run, `NonCallableCommandError`'s message then ends with one more sentence, `To pass "completion" as an argument, write -- before it.`, naming the word the operator typed, alias or canonical name, and its new `argument: string | undefined` member holds that word. It is `undefined` on every other run, an invocation by name included, because a call by name routes by path and has no word to escape. So `textstat completion` reads `Command "completion" requires a subcommand. Use one of: bash, zsh, fish, powershell, install, update, uninstall. To pass "completion" as an argument, write -- before it.` Its constructor gains an optional third parameter, `argument?: string`, so `new NonCallableCommandError(path, candidates)` still compiles. The class, code, exit, and rank are unchanged. No other failure gains the sentence: the unknown-command error and a structural fault raised below such a child, as in `textstat completion notes.txt` or `textstat completion --lines`, read as they read today.
- **Help.** A Command with an action and a visible child prints the action form and the children form, as today, so textstat's page reads `textstat [files...] [options]` and `textstat <command> [options]`. On a Command that declares at least one argument, holds a visible child, and does not declare the passthrough mode, the ARGUMENTS block ends with one more row, whose left cell is `--` and whose right cell is `Read every later word as an argument, even a command name.` The man page follows help.
- **`locate()`.** The `command` position gains `argument: ArgumentNode | null`: the argument the word fills when it names no child, which is the routed Command's first argument on a Command that declares one, and `null` otherwise. No position kind is added, so a reader that switches over `kind` keeps compiling. The completion plugin offers, at a `command` position, the canonical names of the node's children with their descriptions and then the values the `argument` offers under its `argument` rule. With an `argument` that has no closed set, it offers the children's names with directive `0` rather than `4`, so when no child's name starts with the prefix the shell completes file names, as Cobra's scripts do: `textstat co<Tab>` offers `completion`, and `textstat a<Tab>` completes file names.
- **Unchanged.** `CommandNode` and the manifest's Command entry already carry `arguments` and `children` side by side, so neither changes shape. `invoke` routes by its path and fills arguments from `values.args`, so it routes the shape with no change. The MCP plugin serves an opted-in Command with an action as a tool whatever children it holds, so it is unchanged.

The contract is in [Application declarations](../core/application.md), [Nested Commands and groups](../core/commands.md#nested-commands-and-groups), [Global consumption and routing](../core/commands.md#global-consumption-and-routing), [Declaration faults](../core/declaration-faults.md), [Plugin Commands](../core/plugin-contract.md#plugin-commands), [Passthrough](../core/options.md#passthrough), [Locating a word](../core/graph-inspection.md#locating-a-word), [Failure classes](../core/failures.md#failure-classes), the [help page](../plugins/help-page.md), and [Completion](../plugins/completion.md).

## Considered options

- **An opt-in call per Command.** Rejected. Today a Command with children declares no arguments, so no existing application changes when the shape is always allowed, and an author who declares both has chosen it by writing it. An opt-in call adds a builder method, its types, a manifest fact, and a fault that tells every textstat-shaped application to add it, which is ceremony no projection needs.
- **A near-miss note at `-v` or a hint on the failure.** Rejected. A note at `-v` is a new verbose fact for a guess, and a hint added to the run's failure puts Loom's voice inside a failure the author's action wrote.
- **A new `locate()` position kind.** Rejected. `WordPosition` is a sealed union, so a new kind breaks every exhaustive switch over it, and completion would need a third branch that repeats the other two.
- **Keep the rule and give each projection plugin an option entry instead of Commands.** Rejected in grooming on 2026-10-23. Plugin Commands stay ordinary Commands under principle 5, and an author's own children under an argument-taking Command gain the same shape.

## Consequences

This is a feature. An application whose root declares arguments can install the plugins that bring Commands, and the textstat example installs completion. A word that is a child's name now routes on such a Command, so an operator passes it as an argument after `--`, which help and the missing-subcommand failure say. A child added in a later release shadows that word as an argument, which is the cost ADR-0004 named, and the release's changelog says when a Command it adds shadows an argument.

The rule identity `@loomcli/core/arguments-beside-children` is retired, so code that matches it no longer meets it. Its diagnostics anchor is removed.

ADR-0004's rule that one Command declares arguments or attaches children, never both, and its consequence that a root with children accepts no arguments, are superseded for a Command with an action. Its group rules stand: a group runs nothing, routing passes through it, an invocation that commits to it is the missing-subcommand error, and an unknown child is the unknown-command error on a Command that declares no argument. The exclusivity [ADR-0025](0025-completed-commands-accept-immutable-extension-configuration.md) carries from ADR-0001 by reference is withdrawn, and with it the rule that `argument()` and `command()` remove each other. ADR-0033's sentence that an application whose root declares arguments cannot install a plugin that brings Commands is withdrawn, along with the arguments-beside-children rule in its list of Command rules, and so is the same limit as [ADR-0063](0063-the-mcp-plugin-serves-opted-in-commands-as-tools.md), [ADR-0073](0073-the-self-update-plugin-replaces-a-script-installed-binary-with-a-verified-release.md), [ADR-0074](0074-the-service-plugin-supervises-one-user-unit-per-application-through-the-installation-record.md), [ADR-0076](0076-the-skills-plugin-installs-an-applications-agent-skills-for-claude-and-the-shared-agents-folder.md), and [ADR-0140](0140-the-help-plugin-attaches-a-help-command-on-opt-in.md) restate it for the MCP, self-update, service, skills, and help plugins. The authoring skill's `structure.md` and `shipping.md` references, which state the limit, are rewritten with the implementation, and so is the help page reference's textstat sample, which shows a root with no children. The [ADR-0034](0034-a-declaration-fault-throws-at-the-earliest-point-that-knows-it.md) fault for arguments beside children, raised at the call, which [ADR-0093](0093-a-value-that-bypasses-the-types-gets-no-rule.md) incorporates, becomes the attach-time and build-time fault for arguments on a group. ADR-0042's `command` position gains its `argument` member. ADR-0055's sentence that routing is unambiguous because a Command with children takes no arguments, and its rejection of stopping routing at a parent's own option, are narrowed: on a Command that declares arguments, the plain word after a parent's own option that names no child is its first argument, and the option's declaration still decides whether that word is its value. ADR-0152's sentence that arguments and children stay exclusive is narrowed to groups. ADR-0159's clause that a word after `--` on a Command with children fills no argument is narrowed to a Command with children that declares no argument. ADR-0004, ADR-0025, ADR-0033, ADR-0042, ADR-0055, ADR-0063, ADR-0073, ADR-0074, ADR-0076, ADR-0093, ADR-0140, ADR-0152, and ADR-0159 carry dated entries.

## Status

Proposed. It moves to accepted in the release PR of the release that ships it.
