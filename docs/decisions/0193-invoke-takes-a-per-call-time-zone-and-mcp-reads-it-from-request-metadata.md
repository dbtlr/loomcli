# ADR-0193 - Invoke takes a per-call time zone, and MCP reads it from request metadata

## Context

[ADR-0059](0059-a-command-runs-by-name-through-invoke.md) runs a Command by name through `invoke`. [ADR-0107](0107-a-run-reads-the-process-through-one-process-handle.md) replaced per-field host overrides with one process handle bound at entry. An action's invocation by name inherits its run's host facts, including its time zone. The `dateTime()` validator uses that zone for a token with no offset unless its declaration pins a zone.

[ADR-0184](0184-the-mcp-plugin-also-serves-its-tools-over-streamable-http-at-an-address-the-operator-names.md) serves concurrent remote callers in one process. Its server-zone rule makes every caller's zone-less date-time token mean the server's local time. A caller already knows its own zone, but declaring an ordinary time-zone input on each Command does not set the host fact the validator reads. Changing the process's zone for one request would change the other callers' runs too.

The time zone therefore needs a per-call option. Reintroducing a general host override would undo ADR-0107's boundary for unrelated facts such as the working directory and environment.

## Decision

- **One option on both doors.** `InvokeOptions<Mapped>` gains `readonly timeZone?: string`. Both `app.invoke(path, values, { timeZone })` and an action's `invoke(path, values, { timeZone })` accept it. Omission or `undefined` keeps the existing behavior: `app.invoke` reads its process handle's zone, and an action's invocation inherits its run's zone.
- **One core check for the per-call zone.** `resolveTimeZone(timeZone: string): string | undefined`, exported from `@loomcli/core`, constructs `new Intl.DateTimeFormat('en-US', { timeZone })` and reads `resolvedOptions().timeZone`. It returns that resolved name unless it starts with `+` or `-`, and returns `undefined` if construction fails or the resolved zone is an offset. Checking the resolved zone also refuses offsets supplied with a Unicode minus (`U+2212`). `UTC` and aliases the runtime accepts are valid. Loom does not trim the input or restrict it to `Intl.supportedValuesOf('timeZone')`, which omits accepted aliases. `host.timeZone` holds the resolved name, following the same spelling rule as the real process handle's `processTimeZone`. The check reads no `process` global, environment variable, or default time zone. Empty and unknown names fail. Core implements this check once in `packages/core/src/host/time-zone.ts`; invoke and the MCP plugin both use this public function. The real process handle's `processTimeZone` resolves through it too, keeping its `UTC` fallback. `check:api` reports the new export as well as `InvokeOptions.timeZone`.
- **A bad option is a usage failure.** An invalid name resolves `failed` with `InputError`, exit code 2, through the ordinary failure view, hints, failure form, and caller's `failure` handler. Its `problems` is empty because `timeZone` is an invocation option, not a declared argument or option. The sentence is `invoke() timeZone is not an IANA time zone name this runtime knows. Use a name such as "Asia/Tokyo".` It lives in `packages/core/src/invocation/messages.ts`, as a constant that repeats no received value. No engine exception text reaches the sentence. This failure occurs during host assembly, before declared-value validation, input validation, middleware, or the action. Existing failures to capture the working directory or release facts keep precedence. Like those capture failures, an invalid `timeZone` fails before the Application's failure views and `onFailure` hooks are installed: the caller's `failure` handler and the outcome receive the `InputError` with exit 2, and its report uses core's default view with no hints. A non-string value that bypasses the TypeScript option type gets no additional rule under ADR-0093.
- **The call's host carries the zone.** A valid supplied zone resolves to the name that replaces only that call's `host.timeZone` before any validator reads the host. It changes neither the bound process handle nor the parent run, siblings, or concurrent calls. A nested action invocation inherits the effective zone from its immediate parent unless it supplies its own `timeZone`, which replaces the zone for that nested invocation and its descendants. No other host fact is settable through a per-call override. An embedding host may still supply `process` on `app.invoke` as ADR-0107 allows.
- **Declared values follow the effective zone.** A call whose effective time zone differs from the zone its reused declared values were validated under validates every declared default and implied value again against its own host, before input validation or middleware. When an action's call supplies an explicit zone, core reads the parent's `host.timeZone` for this comparison, even if the parent's code never read it. A call with no explicit zone reuses its parent's values without forcing that read. It validates the declarations anew, not their previously validated output, and keeps the resulting values and their validation zone with that call for its descendants. A call in the same zone, including an alias that resolves to the same name, reuses the validated values as today; omitting the per-call zone inherits the parent's zone and reuses its values. `app.invoke` continues to validate every declared default and implied value against its own host on every call. Both doors therefore resolve an omitted zone-less `dateTime()` default and a supplied zone-less token in the call's zone, unless the validator pins its own. Revalidation changes no graph or lifecycle-hook cadence.
- **A validator pin is the author's value.** A declaration's `dateTime({ timeZone })` still wins, and a token with an offset or `Z` still names its own instant. The stricter no-offset rule belongs to the per-call option alone. `packages/validators/src/zone.ts`'s `isKnownZone`, used by a `dateTime()` pin, accepts offsets the formatter knows. That predicate and the author's pinned value are unchanged; they do not acquire the per-call option's stricter rule.
- **MCP reads one key per tool call.** The key is `io.github.dbtlr.loomcli/timeZone` in a `tools/call` request's `params._meta`. `ToolCall` in `packages/mcp/src/protocol.ts` gains the request's optional `_meta` object, passed through without interpreting this key. `packages/plugins/src/mcp/serve.ts` reads the key in the shared tool-call handler, over stdio and HTTP and on every served protocol revision. A valid string is passed as `invoke`'s `timeZone`. An absent key omits the option and keeps the server's zone. It is not an HTTP header, an initialize setting, a session default, or a tool argument, and adds no tool-schema property. Other metadata keys keep their existing meanings.
- **Bad MCP metadata is a tool error.** A present value that is not a string, including `null`, or is a string that makes core's public `resolveTimeZone` return `undefined`, returns one text content item with `isError: true` and no `structuredContent`. No invocation starts. The sentence is `Metadata key "io.github.dbtlr.loomcli/timeZone" requires an IANA time zone name this runtime knows. Use a name such as "Asia/Tokyo".` It lives in `packages/plugins/src/mcp/messages.ts` and repeats no untrusted value. This is a tool execution error, never a JSON-RPC envelope error. Existing protocol-envelope checks, unknown-tool and non-object-arguments checks, and the check for unlisted argument keys keep precedence. A valid call passes the option beside `exclude`, `failure`, `onProgress`, `signal`, and `view`; none of their rules change.

## Relationships

This record narrows these clauses, leaving every other rule intact:

- ADR-0059's **An invocation by name is an argv invocation without the spelling**, for the explicit per-call zone, and **An invocation is a run with no process**, as amended by ADR-0107, for the inherited or captured time-zone fact alone. Its **One operation, two doors** clause reuses declared-value checks only when their validation zone matches the call's effective zone.
- ADR-0107's **The facts**, that the host's time zone comes from the bound handle, for an invocation by name with an explicit zone or one inherited from its immediate parent. **One process handle per run** still holds: a per-call zone changes a host fact, never the handle. Its rejection of per-field host overrides remains in force for every other fact.
- ADR-0063's **A call is an invocation by name**, whose adapter now passes the metadata zone, and whose failed-call structure does not apply to an invalid metadata value refused before invocation, as it already does not apply to an unlisted argument key.
- ADR-0184's **A call runs where the server runs**, specifically that a call always uses the server's time zone, that nothing from an HTTP request reaches the run, and that the author must declare an ordinary input for a caller's zone. It also narrows that record's rejection of **Per-call caller facts** for this metadata time zone alone. The environment, working directory, and every other server host fact stay the server's.

It also narrows ADR-0191's **Each run's own work stays each run's** clause: an action's invocation reuses validated values only in the same effective zone. ADR-0059, ADR-0107, ADR-0063, ADR-0184, and ADR-0191 carry dated entries. The [failure reference](../core/failures.md#failure-classes) allows an `InputError` for an invocation option with no declared-input problem; ADR-0047's rule against repeating received values remains intact. [ADR-0112](0112-an-invocation-by-name-may-exclude-options-and-the-mcp-plugin-excludes-an-option-its-author-keeps-off-the-tool.md)'s exclusion and per-call scope are unchanged: a nested invocation inherits the time zone, but inherits no `exclude` list. [ADR-0111](0111-the-mcp-plugin-registers-its-server-with-claude-code-and-codex-through-each-agents-cli.md)'s registrations and [ADR-0122](0122-the-mcp-server-serves-the-initialize-handshake-beside-the-per-request-revision.md)'s revision negotiation are unchanged. A zone key alone selects no protocol revision.

## Considered options

- **An ordinary input on each Command.** Rejected for the host zone. Every author would repeat the adapter between that input and validation, and an ordinary input cannot set the host before the same invocation validates other inputs.
- **A general per-call host override.** Rejected. The single exception answers the caller-zone need without reopening the process-handle boundary for every host fact.
- **Changing `TZ` or the process handle.** Rejected. Concurrent calls share a server process and must keep independent zones.
- **A time zone stored on the HTTP session.** Rejected. The option belongs to one invocation, works over stdio too, and lets concurrent requests from one client name different zones.

## Status

Proposed. It moves to accepted in the release PR of the release that ships the implementation.

- 2026-11-19: Proposed with the per-call time-zone contract (LM-551).
