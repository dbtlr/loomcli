# ADR-0150 - An application opts in to an extended version that prints the release facts, runtime, and platform

## Context

`version()` prints one line, `<name> v<version>`, with an optional postfix, from the graph alone. Core already holds how the running copy was built, released, and installed, as the [release facts](../core/release-facts.md) on `host.release`: the build, the release channel, the release asset, and the installation method. An operator filing a bug report, and an agent deciding whether a binary can update itself, cannot read them without a Command the author writes. Other command-line tools print them from their version option: clap's `long_version`, `rustc -vV`, and `gh version` each add build and release facts below the version.

The host holds the platform and the architecture, and no fact names the JavaScript runtime. A plugin reads its run's host and never the `process` global, under [ADR-0107](0107-a-run-reads-the-process-through-one-process-handle.md), so a runtime the version plugin prints has to come from the host.

An agent asks for JSON with `--format json`, and most applications are groups at the root: `notes --version --format json` names no Command. The seams core has today cannot carry that request at a group:

- **`view`** names a view of the routed Command's result. A group declares no result, so `view` reads `null` there and has no name to hold.
- **The failure encoders** read the media type of the selected view, which a group does not have.
- **`ownOptions`** holds a plugin's own options for that plugin alone, so a takeover would have to name the formatter's option to read it, which help declines to do and the version plugin must not do.
- **The option itself** never reaches a group. The formatter's hook declares `--format` on each Command that declares a result, and under [ADR-0055](0055-an-invocation-routes-on-global-options-then-parses-the-routed-commands-words-against-one-table.md) a group declares no local option, so at a group `--format json` is the misplaced-option fault, or the unknown-option fault when no Command below declares `--format`, and the version takeover swallows it.

## Decision

- **The author opts in.** `VersionSettings` gains `extended?: boolean`. With `extended: true`, both `-V` and `--version` print the extended output. The option stays one option with one meaning, and the operator gets no switch between the two outputs. Only `true` turns it on, and without it every byte the plugin writes is unchanged.
- **The version line first.** The extended output starts with the version line, rendered through `versionLine` as before, the postfix and an override included, so a script that reads the first line reads the same text in both modes.
- **A block of six rows.** Below the line, with no blank line, a second declared view, `versionFacts`, renders six rows in a fixed order: `channel`, `build`, `asset`, `installation method`, `runtime`, and `platform`. The labels reuse the release facts' names, `installation.method` spelled as two words. The block is the [records layout](../plugins/pack-views.md#records) for one record: a `dim` label padded to the widest label, a two-space gap, and an escaped `primary` value. The version is not a row, because the line above prints it.
- **The values.** `channel`, `build`, `asset`, and `installation method` are `host.release`'s, and the plugin derives none of them, so a run without a release group prints no channel. `runtime` is `host.runtime`'s name and version joined by a space, such as `bun 1.3.2`. `platform` is `host.platform` and `host.arch` joined by a hyphen, such as `linux-x64`, the spelling `loom build`'s targets and asset names use.
- **An absent fact.** Every row always prints. A fact the run does not hold prints an empty value, which the records layout lays out as it lays out any empty value: the line ends at its label on a terminal, and keeps its padding and gap off one. No placeholder stands in for it.
- **The JSON form.** When the run's media type, read from the middleware's `mediaType` when it runs, is `application/json` or `application/jsonl`, the extended output is one JSON object in place of the line and the block. The object holds eight keys in this order: `name`, `version`, `channel`, `build`, `asset`, `installationMethod`, `runtime`, and `platform`. `name` and `version` are the graph's, the version as declared. The other six are the block's values. An absent fact reads `null`, and every key is always present, as the manifest's absence rule states. The bytes are those the formatter's `json()` and `jsonl()` views write for that object. The object is written through a bare view the plugin does not declare, as the manifest's document is, so no override reaches it. It holds no postfix.
- **The run's media type.** `MiddlewareContext` gains `mediaType`, a getter and a setter, as `view` is. It is the one place a middleware states, and a takeover reads, the media type the run's output is asked in. On a Command that declares a result, it reads the media type the selected view declares, from `ResultNode.mediaTypes` under the name `view` holds when it is read, and `undefined` when that view declares none. An assignment there is the view-selection defect at the dispatch boundary, because the selected view already states the media type and selection stays by name. On a Command that declares no result, a group included, it reads `undefined` until a middleware assigns a string, and the last assignment before the dispatch boundary wins, as for `view`. Core stores the string and never checks it, and nothing renders through it. The [failure view context](../core/failure-views.md#failure-view-context)'s `mediaType` is the same value when the run failed, so a [failure encoder](../core/failure-views.md#failure-encoders) answers a failed run at a group whose middleware stated a media type. `middlewareContext` in `@loomcli/testing` takes `mediaType` as an optional value.
- **A hook's option on a group.** An `onCommandAttach` hook may declare a local option on a group, which an author still cannot. Routing reads it at the group as it reads a parent's own option at a Command with an action and children, so it binds to the Command routing finally reaches by the spelling the operator typed. The group's table holds it. Under the held missing-subcommand fault, the held-fault pass validates it for the declaring plugin's `ownOptions`, as it validates a hook's option on any other routed Command. It reaches no action and no `request`, because a group has neither.
- **The formatter at a group.** The formatter's hook declares `--format` on every group as well: hidden, `control: true`, with the description `Select the output format.`, the short spelling `format()` took, and the validator that accepts `json` and `jsonl`, with `ndjson` for `jsonl`. Its middleware assigns that name's media type to `mediaType` on a group, `application/json` for `json` and `application/jsonl` for `jsonl`. So `notes --version --format json` prints the JSON object at the root of a group application, `notes --format json` writes the missing subcommand as the formatter's JSON line, and `notes --format json list` routes to `list` and selects its `json` view. The option is hidden, because a bare group invocation always fails, so no help page, manifest, or completion script changes.
- **A format the formatter does not know.** `notes --version --format yaml` at a group prints the line and the block and exits 0. The formatter's validator rejects `yaml`, so `ownOptions` holds no `format` and the middleware assigns nothing. The version middleware takes over, and under the takeover rule a takeover never raises a held fault, here the missing subcommand. This is the outcome `notes list --format yaml --version` and `--format yaml --help` already have, and the contract states it so that no reader takes the text for a fallback the plugin chose. Without `--version`, `notes --format yaml` is the missing-subcommand failure, exit 2, which ranks ahead of the rejected value.
- **The host gains a runtime.** `ProcessHandle` and the host gain `runtime: { name: 'bun' | 'node'; version: string }`. The real process's handle reads `bun` and `process.versions.bun` under Bun, a compiled binary included, and `node` and `process.versions.node` otherwise. `mockProcess` defaults to `{ name: 'node', version: '24.0.0' }`. Core copies it at entry and freezes it, as it copies `platform`. It is optional on the handle, so a hand-built handle compiles unchanged; the host always has the member, `undefined` when the handle holds none.

The contract and its acceptance are in [Extended output](../plugins/version.md#extended-output), [Formatter](../plugins/format.md), [Middleware](../core/middleware.md), [Global consumption and routing](../core/commands.md#global-consumption-and-routing), and [Host facts](../core/host.md#host-facts).

## Considered options

- **`-V` keeps the line and `--version` prints the extended output.** Rejected by the owner's ruling: `-V` and `--version` stay one option with one meaning. This split is clap's `version` and `long_version`.
- **An operator switch, such as `--version --verbose`.** Rejected by the owner's ruling. The author decides what the application prints.
- **Omitting an absent fact's row.** Not chosen. The block's rows would change with the build, and an absent fact tells the reader something too. The records layout already prints an empty value as its label alone on a terminal.
- **A placeholder such as `none` or `unknown`.** Not chosen. A placeholder reads as a value, and a release channel is an open set of names.
- **A `version` row in the block.** Not chosen. The line above prints the version, and the release group's version matches it for an application built from its package.
- **Reading `--format` by its option name.** Rejected. The version plugin would name another plugin's option, which help declines to do for the formatter.
- **Printing the text block at a group root, and documenting the limit.** Rejected by the owner's ruling, which asks that `tool --version --format json` print the JSON object at the root.
- **Choosing the JSON form from `view` alone.** Rejected for the root. A group declares no result, so `view` reads `null` and no view name can hold the request. The first contract took this rule and printed the text block at a group root.
- **A special case inside the version plugin.** Rejected. Reading `host.argv` for `--format` would name the formatter's option and parse a second time beside core's one grammar. `mediaType` is one seam the formatter writes and any takeover reads, help included if it ever needs one.
- **A global `--format`.** Rejected. A plugin's global option collides with the formatter's local `--format` on every Command that declares a result, and it would add a row to every help page.
- **A visible `--format` on a group.** Not chosen. A bare group invocation always fails with the missing subcommand, so a help row would advertise an option whose only effect at the group is the encoding of a takeover's output or a failure. Hidden keeps every listing's bytes.
- **Reading a group's option in the routed Command's words alone, not in routing.** Rejected. `notes --format json list` would then read `list` as an argument of the root and fail with `The root Command accepts no arguments.`, where today it names the Command that declares `--format`.
- **A failure encoder that keeps reading the selected view alone.** Rejected. A run would then have two answers to which media type it was asked in, and at a group `notes --format json` would print a JSON takeover but a text failure.
- **Raising the usage failure for an unknown format under `--version`.** Rejected. A takeover never raises a held fault, and `--format yaml --help` already prints the page.
- **A `mediaType` assignment that wins over the selected view.** Rejected. Selection stays by name under [ADR-0061](0061-a-view-declares-its-media-type-and-a-result-publishes-it-by-view-name.md), and a second way to choose would let a media type and the view that renders disagree.
- **The runtime from `host.program`.** Rejected. A compiled binary's program is the binary itself, and the program names no version.
- **`platform` with the C library, such as `linux-x64-musl`.** Not chosen. Core reads `libc` on first read from a costly runtime report, and a compiled binary's asset name already carries it.
- **The JSON form through `versionFacts`.** Rejected. The JSON form is data, so an override that restyles the block must not change it.

## Consequences

`VersionSettings` gains `extended`, `@loomcli/plugins/version/views` gains `VersionFacts` and `versionFacts`, `MiddlewareContext` gains `mediaType`, `middlewareContext`'s values gain an optional `mediaType`, and the host, `ProcessHandle`, `ProcessFields`, and `mockProcess`'s fields gain `runtime`, in one feature fragment. `MiddlewareContext` and the host are output types under [ADR-0137](0137-a-published-export-is-public-and-its-tag-says-whether-it-is-an-input-type-or-an-output-type.md), so a new member breaks nothing. `runtime` is optional on the handle and `mediaType` on `middlewareContext`'s values, so no application or test has to change. Each new export and member carries a doc comment under [ADR-0147](0147-every-published-export-and-member-carries-a-doc-comment-and-every-value-an-example.md).

The JSON form reads `mediaType` when the version middleware runs. The middleware takes over, so the formatter has to be installed ahead of `version()` for `--format` to reach it. That is the existing order rule of a takeover chain, which `--help --version` already follows.

With the formatter installed, three group invocations change, each still a failure with code 2 or now a success. `notes --format json` reports the missing subcommand as the formatter's JSON line, where it reported the misplaced option as text. `notes --format json list` runs `list` with its `json` view, where it reported the misplaced option. `notes --format json plain`, where `plain` registers an action and declares no result, reports the unknown option on `plain`, where it reported the option misplaced at the root. Without the formatter no group invocation changes.

The JSON object's key order is a contract that `eslint/sort-keys` would rewrite, so the implementation turns the rule off for the version middleware's module in a per-file override and pins the order with a test the fixer cannot rewrite, under the repository's conventions.

This record extends [ADR-0107](0107-a-run-reads-the-process-through-one-process-handle.md)'s host with `runtime`, a process fact the real handle reads, and [ADR-0021](0021-every-rendered-byte-passes-through-one-registry-of-replaceable-views.md)'s 2026-09-24 exception for the manifest's bare view to the version plugin's JSON form. It supersedes ADR-0055's rule that no local option is declared on a group for an option a lifecycle hook declares, and widens ADR-0055's routing over a parent's own options from a Command with an action and children to any Command with children. It gives [ADR-0061](0061-a-view-declares-its-media-type-and-a-result-publishes-it-by-view-name.md)'s media type a second run-time reader, the middleware context, while selection stays by name, and makes [ADR-0064](0064-a-failure-class-declares-a-failure-code-and-a-plugin-encodes-the-failure-form-by-media-type.md)'s failure selection read that value on a Command that declares no result. ADR-0021, ADR-0055, ADR-0061, ADR-0064, and ADR-0107 carry dated entries.

## Status

Proposed. It moves to accepted in the release PR of the release that ships it.
