# ADR-0082 - An action asks through the prompts library, and one interaction decision governs questions and conditional requiredness

## Context

An application's setup wizard asks an operator for each answer at a terminal and, without one, must take every answer from options or refuse. Today each application writes its own key reader on `host.stdin`, its own test for a terminal, and its own rule for what a pipe does. [Content inputs](0081-content-inputs-prepare-lazy-handles-and-one-command-claims-stdin.md) already leave keyboard interaction to prompts: terminal stdin is never a content source.

Several facts in core shape the answer.

- **Supplied values.** Core already builds the raw value of every supplied input, the `supplied` record of the [validation context](0005-validation-delegates-to-standard-schema.md), but only a validator can read it, and [ADR-0032](0032-environment-and-configuration-map-into-options-through-one-core-input-source-stage.md) keeps the source of a value out of the action.
- **No terminal by name.** An [invocation by name](0059-a-command-runs-by-name-through-invoke.md), and so every [MCP](0063-the-mcp-plugin-serves-opted-in-commands-as-tools.md) tool call, reads every terminal fact as not a TTY, with an empty stdin.
- **A point before validation.** After the [input-source stage](0032-environment-and-configuration-map-into-options-through-one-core-input-source-stage.md), a Boolean global option's value is final, because a Boolean has no validator, and the single validation pass has not started.
- **No way to draw.** An action reaches stderr only through the semantic methods, which add a glyph and a newline, and core strips terminal controls unless the whole application preserves them. [ADR-0021](0021-every-rendered-byte-passes-through-one-registry-of-replaceable-views.md) sends every rendered byte through a replaceable view.
- **No way to cancel from code.** In raw mode Ctrl-C arrives as a byte, not as `SIGINT`. Nothing an action can call ends the run as cancelled under [ADR-0018](0018-one-run-signal-carries-cancellation-and-one-owner-brackets-process-signals.md), whose rule for terminal state is a synchronous listener on the run signal.

## Decision

- **A library, not a plugin.** `@loomcli/prompts` is a separate package that an action imports. It exports `text`, `secret`, `confirm`, and `select`, each called as `await text(context, settings)` with the action's own context, and `InteractionUnavailableError`. Its declared views live in `@loomcli/prompts/views`. An application installs nothing to use it, and it registers no option. It depends on `@loomcli/core` for the action context, validation, and input errors, and owns its key reader and its rendering. It depends on no prompt library.
- **A question is part of the action.** The action calls a question where it wants it, so presentation the action writes first stays visible whether or not the question is asked. Loom never asks on an action's behalf in any run stage, so `--help` and every input failure surface before any question.
- **One interaction decision per run.** Core computes it after the input-source stage and before the validation pass: on only when `host.terminal.stdin.isTTY` and `host.terminal.stderr.isTTY` are both true and the marked option, when the application declares one, has not turned it off. Application intent can turn interaction off and never on. An invocation by name, and so every MCP tool call, is off through its terminal facts, without a rule of its own. The action reads the decision as `interactive`, and conditional requiredness reads the same decision.
- **The mark.** `interaction: true` on a Boolean global option makes that option's final value the application's intent: `false` turns interaction off. At most one option of an Application carries the mark. The mark on a local, string, content, or counted option, and a second marked option, are declaration errors.
- **The interaction plugin.** `@loomcli/plugins/interaction` exports `interaction(settings?)`, which declares the global Boolean option `input` with negative polarity, so the operator types `--no-input`, and the mark. Its optional `env` setting binds a variable the author names. An application that wants another spelling marks its own option instead.
- **Conditional requiredness.** A local string option that takes one value may declare `required: 'non-interactive'`. When interaction is off, it is required, and an omission is the ordinary missing-input problem with exit 2 before the action, whose sentence reads `Option "--port" is required when input is not interactive. Supply a value.` When interaction is on, an omission is plain absence, so the action can ask. The action value keeps `undefined`. A default or `validateOmitted` beside it is a declaration error, as beside `required: true`, and a global option still declares no presence rule under [ADR-0044](0044-a-global-option-declares-no-presence-rule.md). `inspect()` keeps `required` Boolean, `false` for such an option, and publishes the condition in a new field, `requiredWhen: 'non-interactive'`, `null` otherwise, because a manifest field keeps its meaning across releases. Help prints it as the fact `required when not interactive` and leaves it out of the usage line, the manifest copies it, and an MCP tool schema lists it as required, because a tool call is never interactive.
- **A link.** `option: 'port'` links a question to a local option of the routed Command. Text, secret, and select link a string option that is not multiple, and confirm links a Boolean option. The types check that the key names an option of the action, and the library rejects a global option, an undeclared key, and an option of another kind as a defect. `skipIfSupplied: true` is a separate setting. An unlinked question is allowed.
- **Supplied values reach the action.** The action context gains `supplied`, the same `SuppliedInputs` record a validator reads. It says whether a value was supplied and holds its raw text, and never says which source supplied it. A declared default is not supplied.
- **Resolving a linked question.** A skipped question returns the option's validated value from `options` without running the question's validator. A question is skipped when interaction is off and the option was supplied, or when interaction is on, the option was supplied, and `skipIfSupplied` is true. A question that is asked is prefilled by the first that applies: the raw supplied value, the question's own default, the linked option's declared default, or nothing. A Boolean option's implicit absent value is never a default. With interaction off and the option unsupplied, the question fails with core's ordinary missing-input error for that option, exit 2, built by the core export `missingInputError(context, name)`, which names the option as the run names inputs, by spelling from argv and by declared name from an invocation by name, and whose fix for a Boolean option names the spellings its polarity accepts. A default never answers a question when interaction is off.
- **An unlinked question with interaction off.** It fails with `InteractionUnavailableError`, failure code `interaction-unavailable`, exit 1, whose sentence names the question and the Command: `The question "Install the background service?" needs an interactive terminal, and this run is not interactive. Run "mimir setup" at a terminal.` Exit 1 says no operator input fixes it. An unlinked question is an authoring choice that only the author can change, and an MCP caller reads the same sentence.
- **Validation belongs to whichever path answered.** An answer that is submitted, typed or an accepted prefill, goes through the question's own optional `validate`, a Standard Schema value, and a rejected answer shows the issue and asks again. The question's validator may transform, and its output is the question's return type. Without one, text and secret return the string, confirm returns a Boolean, and select returns the chosen string. A linked question's return type is the union of the two paths' types, which collapses to one type when they agree. Keeping the option's validator and the question's validator aligned is the author's work.
- **Four kinds.** Text shows its prefill as a dim hint that typing replaces and clearing restores. Enter on the hint accepts it, and without one Enter submits the empty string for the validator to judge. Secret echoes nothing and shows nothing beyond its title, takes no default or prefill in this release, so it asks empty even when its option was supplied, and its answered line holds no value. Confirm is typed and submitted with Enter, accepts `y`, `n`, `yes`, and `no` in any case, shows `[Y/n]`, `[y/N]`, or `[y/n]`, and answers anything else with `Type y or n.`. Select moves with the arrow keys and selects with Enter, starts on the supplied or default value when it matches a choice and otherwise on the first, shows at most seven choices at once with markers for the hidden ones, and does not wrap. Only select shows a key-help line. Keys typed ahead of a question stay queued for it, as a cooked terminal keeps them.
- **The look.** A question asks on one line in the lane gutter, `? Service port › 4317`, and collapses to `? Service port · 8080` once answered. An invalid answer's issue stays on the line below, `✘ <issue>`, until the next Enter. A question that is skipped prints nothing. Every frame renders through a declared view of `@loomcli/prompts/views`, so the theme, the rendering policy, glyph forms, and character widths apply, and an application restyles a frame with `override`. A secret's typed text never reaches a view.
- **Drawn on stderr through `out.draw`.** `Out` gains `out.draw(data, view)`, which renders a view to stderr, resolved by stderr's rendering policy, keeps terminal control sequences for that call alone when stderr is a terminal, adds no newline, keeps the run's call order with every other `out` write, and resolves to the number of rows the drawn text took, so a question erases exactly what an overridden view drew. The library writes its own cursor movement and erasure through `out.draw` with a bare view. Questions never write to stdout, so a piped result never holds one.
- **Leaving a question.** The action context gains `cancel()`, which aborts the run signal with the reason `{ source: 'action' }`, so the run resolves 130 through ADR-0018's ordinary path. Before it enters raw mode, a question adds a synchronous listener to the run signal that leaves raw mode. Every path out of a question also pauses stdin, removes the question's listeners, and draws its last line with the cursor shown. Ctrl-C at a question calls `cancel()`, and the question throws the signal's reason, which core reads as a silent cancellation. Stdin ending, or Ctrl-D with nothing typed, while a question is active takes the same path, and neither accepts a default nor submits an empty answer. No question returns a cancellation value the action must check.
- **No limit on the author's code.** A question waits as long as the operator takes. Loom adds no timeout, no guard against two questions at once, and no rule about where an action asks. `--yes`, follow-up questions that depend on earlier answers, and gating a destructive action stay the application's.

The contract and its acceptance are in the [prompts reference](../prompts.md), [Interaction](../core.md#interaction), and [Interaction plugin](../core.md#interaction-plugin).

## Considered options

- **Prompts as a plugin, or a subpath of the plugin pack.** Rejected. An installed plugin cannot add a typed member to the action context, so it would do nothing an import does not, and a subpath with no plugin definition breaks [ADR-0020](0020-first-party-plugins-ship-in-one-package-as-subpaths.md)'s rule that each subpath is a plugin.
- **The decision as a host field.** Rejected. The decision depends on a parsed option, which is not a fact of the host, and a whole-field host override would bypass the application's intent.
- **A function on the Application that decides interaction.** Rejected. No Application setting runs code at this phase, and the function would read global string options before validation. A plugin slot with a hook was rejected for the same reason, and because one option field does the job.
- **The option's validator checks a typed answer.** Rejected. A question needs messages and transformations of its own, and a skipped question already returns the option's validated value.
- **A declared default that answers when interaction is off.** Rejected. The question asks because the author wants the operator to choose, and a default that answers a pipe decides for them.
- **Drawing on stdout.** Rejected. A piped result would hold the question, and interaction would depend on stdout as well.
- **Writing `host.stderr` directly with `terminalControls: 'preserve'`.** Rejected. It bypasses the theme, which only core resolves, the order of writes, and stream error handling, and it turns off control stripping for every write of the application.
- **Self-delivered `SIGINT` on Ctrl-C.** Rejected. With no signals owner, the process ends without unwinding and can lose queued output, and a test that runs Loom with an injected host would be killed.
- **A cancellation value or a catchable error.** Rejected. A value the action checks after every question is easy to forget, and an error such as Inquirer's `ExitPromptError` exits 1 and tells a script the command failed rather than stopped.
- **Inquirer or clack.** Rejected. Each reads color support from the process rather than from the host and Loom's rendering policy, and Inquirer installs process listeners, which ADR-0018 leaves to the one signals owner.
- **A Command that declares it needs a terminal.** Deferred to a later release. Nothing needs it today.

## Consequences

A linked question reports a missing input from the action, after dispatch, with exit 2, which narrows [ADR-0006](0006-absence-rules-and-no-lenient-input.md)'s rejection of presence rules inside the action. Conditional requiredness keeps the rule in validation wherever the author declares it. The action context's `supplied` narrows ADR-0032's clause that nothing publishes provenance: an action can tell a supplied value from a default, and still not which source supplied it. `cancel()` and the `action` source of `CancellationReason` add a cause to ADR-0018's two. The MCP tool schema lists a conditionally required option under ADR-0063. `out.draw` keeps terminal controls for its own call at a terminal, which narrows [ADR-0022](0022-renderers-return-marked-strings-that-core-resolves-and-a-theme-is-a-palette.md)'s one `terminalControls` policy and [ADR-0027](0027-core-resolves-marked-output-and-one-theme-contribution.md)'s resolution of embedded ANSI under it. Each of those records carries a dated entry.

`ActionContext` gains `supplied`, `interactive`, and `cancel`, `Out` gains `draw`, `OptionNode` and the manifest's option entry gain `requiredWhen` and, on a Boolean option, `interaction`, the option configuration accepts the `interaction` mark, and core exports `missingInputError`. The plugin pack gains `interaction`, and a new package, `@loomcli/prompts`, joins the synchronized release. The glossary gains Interaction decision, Interaction mark, Conditional requiredness, Question, and Linked option.

## Status

Proposed. It moves to accepted with the release that ships `@loomcli/prompts`, the interaction plugin, and the core additions, proven by PTY tests for each kind, the prefill, the skip, the retry, secret's empty echo, cancellation, and end of input, by process, invocation-by-name, and MCP tests for every path with interaction off, and by type tests for the link and the return types.
