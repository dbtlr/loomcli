# Decision records

Each record captures one hard-to-reverse decision, the reasoning behind it, and the alternatives it rejected. Read the index while planning and reviewing, and open a record before touching the area it governs. The [glossary](../glossary.md) supplies the vocabulary the records use.

## How a status binds the work

| Status       | Binding                                                                                                                                                                                      |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `accepted`   | Load-bearing. Code and plans rely on it, a violation fails acceptance, and its language is locked. Changing it means writing a new record that supersedes it.                                |
| `proposed`   | Records the agreed shape ahead of the code that will enforce it. A violation is a warning that re-opens the decision or the feature, not an error. Details may still move before acceptance. |
| `superseded` | Kept for history. It names the record that replaced it and no longer binds anything.                                                                                                         |
| `deprecated` | Kept for history. The feature it governed was retired, or the proposal was rejected. Its closing section records why.                                                                        |

## Adding a record

ADR-0007, ADR-0008, and ADR-0020 remain accepted except for the specific clauses superseded by [ADR-0027](0027-core-resolves-marked-output-and-one-theme-contribution.md). ADR-0020 and ADR-0025 also remain accepted except for the clauses [ADR-0031](0031-a-plugin-supplies-facts-to-another-plugins-projection-through-a-collecting-extension.md) supersedes: ADR-0020's clause that a subpath imports nothing from a sibling, and, for a collecting extension alone, ADR-0025's replacement clause. ADR-0002, ADR-0004, ADR-0010, ADR-0018, ADR-0022, ADR-0025, ADR-0026, and ADR-0033 remain accepted except for the clauses on when a declaration fault throws, including the ADR-0019 clause ADR-0025 carries and the ADR-0024 clause ADR-0026 carries, which [ADR-0034](0034-a-declaration-fault-throws-at-the-earliest-point-that-knows-it.md) supersedes: their rules stand, and each throws at the call, the attach, or the build that record assigns. ADR-0005 remains accepted except for its rejection of per-value validators, and ADR-0006 except for its rule that a multiple option or variadic argument always runs its validator and its rejection of presence rules in the action, which [ADR-0036](0036-each-value-passes-the-same-validator.md) supersedes. ADR-0032 remains accepted except for its clause that every throw from a configuration source is a fault of that plugin, which [ADR-0038](0038-a-configuration-source-warns-and-reports-input-problems-through-the-ordinary-channels.md) supersedes for a thrown `InputError`. ADR-0038 in turn remains accepted except for its clause that every throw other than an `InputError` stays a plugin fault, which [ADR-0045](0045-a-failure-class-declares-its-exit-code.md) supersedes for any `LoomError` the resolver throws, reported with its class's code, and [ADR-0049](0049-a-translator-turns-a-foreign-throw-into-a-failure-class.md) for a foreign throw a translator answers. ADR-0045 remains accepted except for its clauses that `LoomError`'s constructor takes the message alone and that a plain `Error` from a source always stays the plugin fault, which ADR-0049 narrows. ADR-0032 also remains accepted except for its clause that nothing publishes which tier supplied a value, which [ADR-0040](0040-help-derives-compact-or-extended-from-the-spelling-the-operator-typed.md) narrows: a middleware reads the spellings of its own plugin's options. ADR-0002 remains accepted except for its clause that a completion consumer reads aliases, which [ADR-0043](0043-shell-completion-follows-cobras-protocol-and-never-evaluates-typed-text.md) supersedes: completion reads no alias. ADR-0026 remains accepted except for its clause that a global option takes the same configuration as `option()`, which [ADR-0044](0044-a-global-option-declares-no-presence-rule.md) supersedes for `required` and `validateOmitted`. ADR-0028 and ADR-0013 remain accepted except for their clause that each hook receives what the previous returned, which [ADR-0046](0046-a-failure-view-reads-where-the-run-was-and-plugins-add-hint-lines.md) narrows for `onFailure`: hints accumulate. ADR-0037 remains accepted except for its clause that issues carry no code, which [ADR-0048](0048-a-validator-package-declares-one-issue-code-per-sentence.md) supersedes. ADR-0046 remains accepted except for its clause that `candidates` on the routing errors is unchanged, which [ADR-0047](0047-an-operator-message-says-what-went-wrong-and-what-to-do-instead.md) narrows for deprecated children. ADR-0039 remains accepted except for its JSON-only file format, its fixed user file name, and its clause that TOML and YAML stay out, which [ADR-0054](0054-the-configuration-plugin-reads-toml-and-yaml-files-chosen-by-the-authors-file-pattern.md) supersedes once accepted: the extension chooses the parser, and the user file name is an author setting that defaults to `config.json`.

Number the file after the highest existing record. Use the frontmatter fields the existing records carry: `type`, `title`, `description`, `status`, `created`, `modified`, and `superseded_by` when it applies. A record needs a context section; add considered options or consequences only when they carry information a reader would otherwise have to rediscover. A `proposed` record adds a status section stating what would move it to accepted. Record later status changes and addenda as dated entries in a closing changelog section rather than editing the decision text.
