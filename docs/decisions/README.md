# Decision records

Each record captures one hard-to-reverse decision, the reasoning behind it, and the alternatives it rejected. Read the index while planning and reviewing, and open a record before touching the area it governs. The [glossary](../glossary.md) supplies the vocabulary the records use.

## How a status binds the work

| Status       | Binding                                                                                                                                                                                      |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `accepted`   | Load-bearing. Code and plans rely on it, a violation fails acceptance, and its language is locked. Changing it means writing a new record that supersedes it.                                |
| `proposed`   | Records the agreed shape ahead of the code that will enforce it. A violation is a warning that re-opens the decision or the feature, not an error. Details may still move before acceptance. |
| `superseded` | Kept for history. It names the record that replaced it and no longer binds anything.                                                                                                         |
| `deprecated` | Kept for history. The feature it governed was retired, or the proposal was rejected. Its closing section records why.                                                                        |

## Adding a record

ADR-0007, ADR-0008, and ADR-0020 remain accepted except for the specific clauses superseded by [ADR-0027](0027-core-resolves-marked-output-and-one-theme-contribution.md). ADR-0020 and ADR-0025 also remain accepted except for the clauses [ADR-0031](0031-a-plugin-supplies-facts-to-another-plugins-projection-through-a-collecting-extension.md) supersedes: ADR-0020's clause that a subpath imports nothing from a sibling, and, for a collecting extension alone, ADR-0025's replacement clause. ADR-0002, ADR-0004, ADR-0010, ADR-0018, ADR-0022, ADR-0025, ADR-0026, and ADR-0033 remain accepted except for the clauses on when a declaration fault throws, including the ADR-0019 clause ADR-0025 carries and the ADR-0024 clause ADR-0026 carries, which [ADR-0034](0034-a-declaration-fault-throws-at-the-earliest-point-that-knows-it.md) supersedes: their rules stand, and each throws at the call, the attach, or the build that record assigns. ADR-0005 remains accepted except for its rejection of per-value validators, and ADR-0006 except for its rule that a multiple option or variadic argument always runs its validator and its rejection of presence rules in the action, which [ADR-0036](0036-each-value-passes-the-same-validator.md) supersedes. ADR-0032 remains accepted except for its clause that every throw from a configuration source is a fault of that plugin, which [ADR-0038](0038-a-configuration-source-warns-and-reports-input-problems-through-the-ordinary-channels.md) supersedes for a thrown `InputError`. ADR-0038 in turn remains accepted except for its clause that every throw other than an `InputError` stays a plugin fault, which [ADR-0045](0045-a-failure-class-declares-its-exit-code.md) supersedes for any `LoomError` the resolver throws, reported with its class's code, and [ADR-0049](0049-a-translator-turns-a-foreign-throw-into-a-failure-class.md) for a foreign throw a translator answers. ADR-0045 remains accepted except for its clauses that `LoomError`'s constructor takes the message alone and that a plain `Error` from a source always stays the plugin fault, which ADR-0049 narrows. ADR-0032 also remains accepted except for its clause that nothing publishes which tier supplied a value, which [ADR-0040](0040-help-derives-compact-or-extended-from-the-spelling-the-operator-typed.md) narrows: a middleware reads the spellings of its own plugin's options. ADR-0002 remains accepted except for its clause that a completion consumer reads aliases, which [ADR-0043](0043-shell-completion-follows-cobras-protocol-and-never-evaluates-typed-text.md) supersedes: completion reads no alias. ADR-0026 remains accepted except for its clause that a global option takes the same configuration as `option()`, which [ADR-0044](0044-a-global-option-declares-no-presence-rule.md) supersedes for `required` and `validateOmitted`. ADR-0028 and ADR-0013 remain accepted except for their clause that each hook receives what the previous returned, which [ADR-0046](0046-a-failure-view-reads-where-the-run-was-and-plugins-add-hint-lines.md) narrows for `onFailure`: hints accumulate. ADR-0037 remains accepted except for its clause that issues carry no code, which [ADR-0048](0048-a-validator-package-declares-one-issue-code-per-sentence.md) supersedes. ADR-0046 remains accepted except for its clause that `candidates` on the routing errors is unchanged, which [ADR-0047](0047-an-operator-message-says-what-went-wrong-and-what-to-do-instead.md) narrows for deprecated children. [ADR-0054](0054-the-configuration-plugin-reads-one-file-per-run-found-by-the-authors-file-pattern.md) supersedes ADR-0039's layered files, its `files` setting, its derived user file, and its JSON-only format, and ADR-0039 remains accepted only for the `--config` option, the named file strict and a discovered file lenient, reading only when some value is needed, a wrong value as a usage failure, the value shapes, dotted paths, and fixed, escaped text. [ADR-0055](0055-an-invocation-routes-on-global-options-then-parses-the-routed-commands-words-against-one-table.md) supersedes the ADR-0003 provisions ADR-0026 carries for the global pre-scan, the first-hyphen commit, the mixed-scope fault, and the rejected per-Command table, and ADR-0017's plugin option class; ADR-0026 and ADR-0017 remain accepted for everything else, and ADR-0004, ADR-0013, ADR-0028, ADR-0032, ADR-0040, ADR-0042, and ADR-0044 carry dated entries.

[ADR-0058](0058-help-owns-ordered-sections-with-at-most-two-heading-levels.md) narrows ADR-0033's consequence that plugin-attached Commands lead the root help page: authored section order may place another section first. Attachment order and the manifest's child order remain unchanged.

[ADR-0064](0064-a-failure-class-declares-a-failure-code-and-a-plugin-encodes-the-failure-form-by-media-type.md) narrows ADR-0021's rule that every rendered byte resolves through the registry, and ADR-0023's clause that no encoding exists outside the view model, for one write: the line a failure encoder writes to stderr in place of a failed `run()`'s failure view. That run writes no `incompleteResult` line, which narrows ADR-0023's rule that a stopped sequence always writes one. A result's encoding stays in its views. ADR-0064 also narrows ADR-0055's validation pass and ADR-0032's clause that a source failure stops the stage: under any held fault, structural, input-source, or validation, core still validates a plugin's own options whose tokens parsed, for that plugin's middleware alone, and the held fault stays the one raised.

[ADR-0065](0065-release-facts-on-the-host-say-how-the-running-application-was-built.md) supersedes ADR-0050 whole and reverses its rule that no packet is distributed: no baked facts reads as `source`. It narrows ADR-0009's host capture, which gains `release`, a field core reads from the build rather than the process, and ADR-0059's host override set for `app.invoke`, which gains it too, and ADR-0059's clause that both doors render by the Application's packet: both render by the run's release facts. It narrows ADR-0051 where that record reads the build: a development build is one whose facts read `source` or `development`, and malformed baked facts render their Developer Diagnostic in every build. [ADR-0067](0067-a-packages-changelog-cuts-its-version-from-three-fragment-kinds.md) generalizes ADR-0012's fragment and manifest rules to any one package and adds a feature kind, and ADR-0012 keeps governing this repository's synchronized release, where a feature fragment advances the patch as a fix fragment does.

[ADR-0066](0066-the-toolchain-acts-on-one-package-directory.md) adds `Application.check()` as a third door to the build rules beside `inspect()` and `run()`, which [ADR-0051](0051-a-developer-diagnostic-teaches-the-author-what-broke-and-how-to-fix-it.md) reads for its Developer Diagnostics, and it changes no moment [ADR-0034](0034-a-declaration-fault-throws-at-the-earliest-point-that-knows-it.md) assigns: a fault at a call or an attach still throws while the module loads, and `inspect()` and `run()` still report the first build fault.

[ADR-0069](0069-core-hands-log-events-to-onlog-hooks-and-writes-no-log-record.md) adds `onLog`, an observing hook, and narrows ADR-0028's and ADR-0013's clause that each hook receives what the previous returned, as ADR-0046 and ADR-0060 did, and ADR-0028's sentence that a hook runs at build, which holds for `onCommandAttach` and `onGraphBuilt` alone. With [ADR-0070](0070-the-logging-plugin-writes-one-json-record-per-event-to-a-size-rotated-file-or-stderr.md) it narrows ADR-0047's No leaks rule, which binds operator messages and not log records, ADR-0064's consequence that no class name reaches a machine reader, which holds for the failure form and not for a log record, and ADR-0063's rule that stderr carries only the `mcp` run's fault, which gains the logging plugin's console records. ADR-0070 narrows ADR-0021: a log record resolves through no view. ADR-0017 and ADR-0046 carry dated entries.
