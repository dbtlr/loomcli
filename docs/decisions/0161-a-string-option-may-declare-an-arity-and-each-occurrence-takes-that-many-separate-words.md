# ADR-0161 - A string option may declare an arity, and each occurrence takes that many separate words

## Context

A string option takes one word per occurrence. A `multiple` option collects repeated occurrences, so `--field a --field b` gives `['a', 'b']`, and a variadic argument takes the plain words the other arguments leave. Neither declares a value made of a fixed number of words, such as a point (`--point 3 4`), a window size (`--resize 800 600`), or a rename pair (`--rename old new`). An author writes such a value as two options, as one word the action splits, or as a `multiple` option whose count the action checks, and help, completion, MCP, and the manifest describe none of them as one value.

Other parsers declare one. clap's `num_args(2)`, argparse's `nargs=2`, yargs' `nargs`, and Clipanion's `arity: 2` each read a fixed number of words after the spelling. clap and argparse also take open-ended counts (`num_args(1..)`, `nargs='+'`), and Commander's variadic options take words until the next option word. An open count reads the plain words after the option as values, so `lint --include a b file.txt` reads `file.txt` as an include. POSIX Utility Syntax Guideline 8 asks for the opposite: several values of one option go in one word, separated by commas or blanks.

The owner settled the shape in grooming (LM-386): a fixed count only, one validator per word, the words separate after the spelling, a delimited variable for a scalar arity option, and arrays in the configuration source.

## Decision

- **The declaration.** A string option, local or global, declares `arity`, a whole number of 2 or more: `.option('point', { arity: 2, type: 'string' })`. Each occurrence then takes exactly that many words. A number that is not whole or is below 2 is a declaration error at the declaring call, [`@loomcli/core/option-arity`](../core/diagnostics.md#loomclicoreoption-arity), with the headline `Invalid option arity`, the explanation `An option with an arity takes exactly that many words per occurrence and gives the action a tuple of them. A count below 2 is the single word an option without arity already takes, and a count that is not whole names no number of words.`, a sentence that names the declaration and the count, as in `Option "point" declares arity 1.`, and the correction `Declare a whole number of 2 or more, or remove arity.` The types reject `arity` beside `implied` and `validateOmitted`, on a Boolean, counted, content, or background option, and beside `env` on a multiple option.
- **The value.** The action reads a tuple of the validator's outputs, one per word, in supplied order. With a literal arity the type is a tuple of that length: `{ arity: 2, validate: integer() }` reads `[number, number]`. With an arity typed as `number`, the type is an array of the output. With `multiple: true`, each occurrence adds one tuple, so the value is a list of tuples. An omitted scalar arity option reads `undefined` unless it is required or declares a default, and an omitted multiple one reads `[]`, as today. A default is a tuple, or a list of tuples on a multiple option, in the validator's input type. `required: true` means at least one occurrence, and `required: 'non-interactive'` applies the same check only when input is not interactive. The missing sentence's fix clause names the count, `Option "--point" is required. Supply 2 values.`, and on a multiple option `Supply at least one set of 2 values.`, in core's report and in `missingInputError` alike; the head, `is required when input is not interactive` included, and the by-name form are unchanged. No question links an arity option, so an action whose option declares `required: 'non-interactive'` asks through an unlinked question and reports an unanswered one through `missingInputError`. The [supplied record](../core/validation.md) holds the raw words in the same shape: a tuple of strings, or a list of them. Shaping the tuple into another value, such as `{ x, y }`, is the action's, as a rule over a multiple option's whole list is.
- **Validation.** `validate` names the validator for one word under [ADR-0036](0036-each-value-passes-the-same-validator.md). Core runs it on each word of each occurrence, in supplied order, and reports each issue at the word's position, counted from 0: `Option "--resize" at 1: Use an integer.` On a multiple option the position names the occurrence, then the word: `Option "--point" at 2.1: Use an integer.` A default's words pass the same validator.
- **Separate words only.** The words an occurrence takes are the separate words after its spelling. A long spelling with `=` and a short letter with the rest of its word attached each carry a value, which an arity option cannot take: `--point=3 4` and `-p3 4` are the `UnexpectedValueError`, exit 2, whose sentence is `Option "--point" takes its values as separate words. Supply each one after "--point" as its own word.` A letter in a short group that ends the group with nothing attached takes the next words, so `-vp 3 4` sets `v` and gives `p` `['3', '4']`.
- **The value class.** An arity option's [value class](../glossary.md#inputs) is a string option that takes that many separate words, one class for each count, so the classes are no longer four. Routing reads a parent's own arity option with its words, as it reads any option's value, so in `app --size 800 600 child` the value is `['800', '600']` and routing sees `child`. The occurrence rebinds to the routed Command's option of that spelling only when both declare the same arity: a parent's `--size` with arity 2 before a child's `--size` without one, or with arity 3, is the held `MisplacedOptionError`, because the words the parent's declaration read are never read again. An occurrence rebound to the same arity keeps the fault the parent's declaration found, so `app --size=8 child` is the `UnexpectedValueError`.
- **Too few words.** A word the grammar never reads as a value, an option word or a bare `--`, ends the occurrence, as does the end of the line. When either comes before the count is met, the occurrence is the `MissingValueError`, exit 2. At the end of the line or a bare `--`, its sentence is `Option "--point" requires 2 values and received 1. Supply 2 values after "--point".` At an option word, it names that word's spelling, so an operator who meant it as a value learns why it was not one: `Option "--rename" requires 2 values, and "--old" reads as an option. Supply 2 values after "--rename"; a value that reads as an option cannot be one of them.` The spelling is the part of a long word before its first `=`, and the first letter of a short group, as an unknown option is named, so an attached value, such as the secret in `--token=s3cret`, never prints, and `-old` prints as `-o`. The words it did take supply nothing, and the word that ended it is read as it would have been. `MissingValueError` gains `arity: number | null`, the count, `null` for an option without one. Its constructor takes an optional third parameter, `{ arity, received, refused? }`, where `refused` is the spelling of the option word that ended the occurrence. An option word, such as `-old` or `--old`, and a bare `--` can never be one of an arity option's values on a command line; `-5` and `-` are plain words and can. Such a value reaches the option through the environment, the configuration source, or an invocation by name.
- **A repeat.** A scalar arity option supplied twice is the `RepeatedOptionError`, as any scalar option is, and the repeated occurrence still takes the words its count names, up to a word that refuses a value, so the words after it read as they would have.
- **The first bare `--`.** An occurrence never takes the `--` or a word after it, under [ADR-0159](0159-passthrough-is-a-mode-a-command-declares-and-required-arguments-may-follow-a-variadic.md).
- **The environment.** A scalar arity option binds `env` beside `envDelimiter`, which the types require there as [ADR-0127](0127-a-multiple-option-binds-a-variable-whose-value-its-authors-delimiter-splits-into-the-list.md) requires it on a multiple option. The variable's value splits at each delimiter, untrimmed and with empty items kept, and must give exactly the declared count of items: `BOX_SIZE=800x600` with `envDelimiter: 'x'` fills `['800', '600']`. Any other count is an `invalid` problem of the run's `InputError` with one issue, which renders in the environment fill's ordinary form, `Option "--size" (from BOX_SIZE): Use 2 values separated by "x".`, exit 2. The types reject `envAllowEmpty` beside `arity`, because an empty variable splits into one empty item and never fills the count, so an empty variable is unset and the option falls through to the next tier. A multiple arity option binds no variable, which the types reject, because one delimiter cannot separate the tuples from their words. The `env:` fact help prints reads `env: BOX_SIZE as 2 values separated by "x"`, and the man page's binding lines read `Environment: BOX_SIZE (2 values separated by "x")` and `Supplies --size as 2 values separated by "x".`
- **Source answers.** A configuration source answers a scalar arity option with a tuple of exactly the declared count of strings, and a multiple arity option with a list of such tuples. An answer of another shape or length is outside the answer rule, the [`@loomcli/core/source-answers`](../core/diagnostics.md#loomclicoresource-answers) defect, as an answer of the wrong raw type is today. The answer is one fill, so a validator that rejects one word drops the whole answer, under [ADR-0117](0117-a-configuration-value-its-validator-rejects-falls-back-and-validates-against-its-files-directory.md), or fails the run for a `strict` answer.
- **The configuration source.** The configuration plugin's link answers a scalar arity option with an array of exactly the declared count of items, `{ "size": [800, 600] }`, and a multiple arity option with an array of such arrays, `{ "point": [[1, 2], [3, 4]] }`, each item following the string rule a multiple option's items follow. Any other value is not answered, as a value an option cannot take is not answered today: the option falls through, and the source's `out.debug` line reads `Use an array of 2 strings or numbers.` or `Use an array of arrays, each of 2 strings or numbers.`, and an option `strict` covers fails the run instead. The `link-type` check accepts a key that holds an array for an arity option, as it does for a multiple one, and its correction reads `... or an array for a multiple or arity option.`
- **Invocation by name.** `invoke`'s `values` takes a tuple for a scalar arity option and a list of tuples for a multiple one, each element a string or a finite number, and lowers each tuple to one occurrence. On a multiple arity option a single tuple is one occurrence, as a single value is on a multiple option, and an empty list is none. A value of another shape or length is the ordinary unlowerable value, with the issue `Use a list of 2 strings or numbers.` on a scalar arity option and `Use a list of 2 strings or numbers, or a list of such lists.` on a multiple one. A word in a tuple may be an option word or a bare `--`, which no command line can spell as an arity option's value. This is a named exception to [ADR-0059](0059-a-command-runs-by-name-through-invoke.md)'s rule that a call by name behaves as the argv that spells it: lowering writes occurrences, never argv text, so a call by name and an MCP client supply such a value.
- **Questions.** No question kind answers a tuple, so a question cannot link an arity option. The prompts library's runtime link check refuses an arity option, as it refuses any other option a question kind cannot answer; the types leave it to that check, because an arity option's tuple and a validator's tuple output are one type.
- **Projections.** The string variant of `OptionNode` gains `arity: number | null`, the declared count, `null` without one, and the manifest's option entry copies it after `multiple`. Help prints the value placeholder once per word, `--point <point> <point>`, in the option row, where a multiple option adds its `repeatable` fact as today and no `...`. The usage line names a required scalar arity option as `--point <point> <point>` and a required multiple one as `(--point <point> <point>)...`, docopt's grouping, so the `...` repeats the whole occurrence rather than its last word. A tuple default prints its words separated by a space under the help page's existing default rule, `default: 800 600`. A man page follows help. Help's `placeholder` stays one word. The MCP plugin publishes a scalar arity option as an array whose `items` is the validator's schema, with `minItems` and `maxItems` at the count, and a multiple one as an array of such arrays. `locate` reads each word after an arity option's spelling as that option's value until the count is met, so completion offers values for each of them, and an occurrence that has taken its words reads the next word afresh. Routing's words are located the same way. `--point=` gives no value position, because an arity option refuses an attached value. Completion offers a scalar arity option once and a multiple one again, as it does for any option.

The contract is in [Option value arity](../core/options.md#option-value-arity), [Commands and global options](../core/commands.md), [Interaction](../core/interaction.md), [Input sources](../core/input-sources.md), [Invocation](../core/invocation.md), [Graph inspection](../core/graph-inspection.md), [Failures](../core/failures.md), [Diagnostics reference](../core/diagnostics.md), [Configuration plugin](../plugins/config.md), [Help plugin](../plugins/help.md), [Help page](../plugins/help-page.md), [Man pages plugin](../plugins/manpage.md), [Manifest plugin](../plugins/manifest.md), [MCP plugin](../plugins/mcp.md), [Prompts](../libs/prompts.md), and the [glossary](../glossary.md#inputs).

## Considered options

- **Open-ended counts, or a minimum and a maximum.** Rejected by the owner's ruling. An open count reads the plain words after the option as values, so it swallows positional arguments unless the operator ends it with `--`. A list of any length is already a `multiple` option or a variadic argument.
- **One word with a separator, as POSIX Guideline 8 asks.** Not chosen. An author who wants it declares a scalar option and a validator that splits the word, as `keyValue()` does. The separate-word form is what clap, argparse, yargs, and Clipanion read, so it is the deviation from Guideline 8 that this record names, under [principle 6](../principles.md#6-standards-before-inventions).
- **A validator per position, or one validator over the tuple.** Rejected by the owner's ruling. A validator per position needs a schema per position in every projection, and a validator over the tuple takes an array that no catalog validator accepts and publishes an array schema the author writes by hand. One validator per word keeps ADR-0036 and every existing validator.
- **The attached value as the first word.** Rejected by the owner's ruling. `--point=3 out.svg` would take `out.svg` as the second value without complaint, and argparse rejects the attached form for a fixed count too.
- **A placeholder list in help, one word per position.** Not taken. A help extension value cannot be checked against its option's arity, so a list of the wrong length would print wrong text without complaint.

## Consequences

A declaration that compiled before compiles and runs the same. One change breaks the types: `SuppliedInputs.options`, which the validation context and the action read, admits a list of tuples, a multiple arity option's raw value, so code that reads each element of an array there as a string adds a narrowing. `OptionNode`'s string variant and the manifest's option entry gain `arity`, a new member of output types. `MissingValueError` gains `arity` and an optional constructor parameter, and `UnexpectedValueError`'s `kind` gains `'arity'`. Core gains one declaration rule. An arity count joins the value class, so a parent's own option rebinds by it. The input-source stage, the configuration plugin, invocation by name, help, the man page, the MCP plugin, `locate`, and the prompts library's link each read the new shape. ADR-0036's value shape, one value or a list of them, gains the tuple and the list of tuples, each word passing the one validator. ADR-0127's binding, which requires `envDelimiter` beside `env` on a multiple option and rejects it on every other option, is narrowed: a scalar arity option binds beside it too, and a multiple arity option binds no variable. ADR-0128's `envAllowEmpty`, allowed on a scalar string binding, is narrowed: an arity option takes none. [ADR-0057](0057-a-counted-option-counts-its-occurrences-and-an-implied-value-fills-a-bare-spelling.md)'s value classes, which [ADR-0055](0055-an-invocation-routes-on-global-options-then-parses-the-routed-commands-words-against-one-table.md) and [ADR-0152](0152-routing-reads-a-groups-own-options-as-it-reads-a-parents-own-options.md) bind a parent's own option by, gain one class per arity count. ADR-0059's argv equivalence is narrowed for a tuple word that is an option word or a bare `--`. ADR-0036, ADR-0055, ADR-0057, ADR-0059, ADR-0127, ADR-0128, and ADR-0152 carry dated entries.
