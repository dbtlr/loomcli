- Fix the operator sentences of `@loomcli/validators`, `@loomcli/prompts`, and the `loom` bin that repeated a value without escaping it, so a control character, a line separator, or a bidirectional control in one prints as its `\uXXXX` escape instead of reaching the terminal. Only a value that holds such a character prints differently. Each changed sentence:
  - The catalog's `Expected one of: <values>.` escapes the values `oneOf()` declares, so `oneOf(['dev', 'pr<U+202E>od'])` rejects with `Expected one of: dev, pr\u202eod.` where it printed the control itself. The same holds for the layouts of `Expected a date as <forms>, such as 2026-09-25.`, `Expected a date and time as <forms>, such as 2026-09-25T14:30:00Z.`, and `Expected a time of day as <forms>, such as 09:30.`, and for the separator of `Expected a key and a value as key<separator>value.`
  - A question's `The question "<message>" needs an interactive terminal, and this run is not interactive. Run "<command>" at a terminal.` escapes the question's message and the command, so a message `Wipe<U+202E> the cache?` prints as `Wipe\u202e the cache?`.
  - Every `loom` sentence that repeats a path, a module, a version, a tag, a commit, a package name, a URL, a `--target` value, or a system's one-line reason escapes it: the failures of `loom build`, `loom init`, `loom changelog`, `loom pr check`, and `loom release`, the warnings and the `Wrote <path>.`, `Removed <path>.`, and `Added <key> to package.json.` lines of `loom init`, the `Built <path> for <target>.` line of `loom build`, and the lines of a release plan and a release record. For example, a fragment folder entry `.changes/no<U+202E>tes.txt` now fails with `.changes/no\u202etes.txt: expected <slug>.md, feature.<slug>.md, or breaking.<slug>.md.` Text another program or a service wrote, such as Bun's build output, git's stderr, or pnpm's report, still prints whole, its lines included.
