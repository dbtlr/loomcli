- Wrap the `@loomcli/plugins/help` page to the terminal's `columns`. The masthead description, a deprecation message, every right cell, Details text, the INPUT block's sentences, option-group sentences, example notes, and hints wrap with hanging indents, and a right cell continues under the right column. Usage forms, section titles and inner headings, left cells, Details code, the INPUT example line, and example commands stay whole, and a Details code span and a hint's command never break. See [Help wraps to the destination's columns](docs/core.md#help-wraps-to-the-destinations-columns).
- Stack the rows under one help heading when their indent, left column, and widest unbreakable word cannot fit `columns`: each left cell prints on its own line and its right cell wraps on the lines below, four columns past the furthest-in start of a left cell's text, so a long-only option's description never starts in its spelling's column. The rows under every other heading keep two columns.
- Reflow a help Details paragraph on a terminal: its authored lines join with one space and wrap to the width, in lists and quotes too, while code keeps every line. On a terminal, tabs on the help page expand to spaces before it wraps. Off a terminal, as on a pipe, under `app.invoke`, and in an MCP tool call, every help page is byte for byte unchanged, tabs included.
