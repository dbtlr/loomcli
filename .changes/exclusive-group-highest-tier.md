- Fix an exclusive option group failing a run because a configuration file or an environment variable filled one member while the operator typed another. The highest input tier that supplies a member now wins: a member a lower tier filled is withdrawn before validation, reads as unfilled with its declared default, and is absent from the `supplied` record. So `json = true` in a configuration file with a typed `--yaml` runs with `yaml`, an environment member wins over a configured one, and the named values of an `invoke()` call win over both. Members one tier supplied still conflict, such as `--json --yaml` or two configured keys, and `oneRequired` and `requiredTogether` still count every tier. A bound variable outside its grammar beside a typed sibling no longer fails the run.
