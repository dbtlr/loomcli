- Add `extended` to `version()`'s settings. With `version({ extended: true })`, `-V` and `--version` print the version line, then one row each for the run's release channel, build, release asset, installation method, runtime, and platform, with an absent fact printed as an empty value. When the selected view declares `application/json` or `application/jsonl`, as `--format json` and `--format jsonl` select with the formatter installed ahead of the version plugin, they print the same facts as one JSON object instead, with `null` for an absent fact. `versionFacts`, exported from `@loomcli/plugins/version/views` with its data type `VersionFacts`, restyles the rows. Without the setting, the version line is unchanged. See [Extended output](docs/plugins/version.md#extended-output).
- Add `runtime` to the host and the process handle: the JavaScript runtime's name, `bun` or `node`, and its version. The real process's handle reads it, `processHandle({ runtime })` and `mockProcess({ runtime })` replace it, and `mockProcess` defaults it to `{ name: 'node', version: '24.0.0' }`. It is optional, so a hand-built handle and a test that states a host whole compile unchanged. See [Host facts](docs/core/host.md#host-facts).
