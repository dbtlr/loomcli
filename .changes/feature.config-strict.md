- Add `strict` to `configuration()`, so a service that a supervisor runs, where nobody reads `-v`, fails on a broken setting instead of falling back in silence. `strict: true` covers the whole file, and a list of dotted key paths, such as `strict: ['delivery']`, covers each path at or under a listed one. A value the schema rejects, an unknown key, or a linked option's value that `strict` covers fails the run with code 2 instead of being dropped, and one failure names every such key with its file and what to do: `collector: Configuration value delivery.retries in .collector.toml: Invalid input: expected number, received string. Correct the value, or remove it.` An unknown key fails the run only where the schema publishes a JSON Schema, so under valibot only a rejected value fails it. Without `strict`, the plugin writes the same bytes as before. The [configuration plugin](docs/plugins/config.md#the-strict-setting) reference states the rules.
- Add `strict` to `SourceAnswer`, so a configuration source can mark an answer whose rejection by the option's validator fails the run with code 2, as an environment value's does, instead of falling back. The [input sources](docs/core/input-sources.md#configuration-sources) reference states the rule.
