- Add the `install` piece to `loom init`. In a package whose `package.json` `repository` names a GitHub repository, init writes `install.sh`, an executable managed file whose header is a `#` comment on the line after `#!/bin/sh`. Under POSIX `sh` on Linux and macOS, `install.sh [--dir <directory>] [<version>]` downloads the platform's binary from the repository's GitHub Release, verifies it against the release's `SHA256SUMS`, moves it into `~/.local/bin` or the `--dir` directory, and writes `install.json` in the installation record with the method `script`. With no GitHub repository, init writes no script and prints a warning that names `repository`. `loom check` warns about an edited `install.sh` as it does for every managed file. See [the installer script](docs/toolchain.md#the-installer-script) for its arguments, output, and the release shape a release workflow publishes for it.
