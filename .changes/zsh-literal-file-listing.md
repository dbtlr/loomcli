- Fix the Zsh completion script running text typed in a file path when Tab lists file names. With Tab bound to `complete-word`, a typed `$(…)/`, such as in `--config $(touch x)/`, ran when the script handed the word to Zsh's `_files` or `_path_files`. The script now lists file names itself and reads the typed folder as text, so the script never runs what was typed. Zsh itself can still expand the word, and the script cannot prevent it: the default Tab widget, `expand-or-complete`, and the `_expand` completer, when the operator's `completer` style lists it, each run a typed `$(…)`. The listing keeps the operator's completion styles, such as `matcher-list` and `format`, and inserts each name exactly, with a leading `~` or `=` escaped. It matches only the last path component, so an abbreviated path such as `D/R` no longer expands to `Docs/Readme.json`. A leading `~/` still lists the home folder; a typed `$HOME/`, `~user/`, `~[x]`, or `=cmd` is read as text.
