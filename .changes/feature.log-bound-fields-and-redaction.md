- Add `log.with(fields)`, which returns a `Log` whose every event carries those fields, copied once, as a pino or winston child logger does. It nests, a call's own field wins over a bound one of the same name, and a bound field fills a message template's placeholder. Every context that carries `log` has it, a log destination's included, and `@loomcli/testing`'s builders' `log` passes the bound fields to the levels a test states. `logDestination` now takes its `log` level by level, as the builders do, so a test that states only `debug` keeps the other levels inert. See [Bound fields](docs/core/logging.md#bound-fields).
- Add `log: { redact }` to the Application options: a list of dotted field paths whose values read `"[Redacted]"` in every log event, so no `onLog` hook, log line at `-v`, or log record sees them. A path steps through arrays, bound fields are redacted too, and Loom redacts nothing an Application does not list. A path that is not dotted nonempty keys is the declaration error `@loomcli/core/invalid-redact-path` from the constructor. See [Redaction](docs/core/logging.md#redaction).
