- Add the skills plugin's `folder` setting, so an application names one folder whose subfolders are its agent skills, such as `skills({ folder: new URL('../skills/', import.meta.url) })`, in place of writing a loader for each skill. `skills` becomes optional, and settings with neither throw `@loomcli/plugins/skills/settings`. A source run and a test read the folder from disk when `skills install` or `skills update` runs, and a folder the plugin cannot read as skills fails with `@loomcli/plugins/skills/folder`. See [The skills folder](docs/plugins/skills.md#the-skills-folder).
- Add the skills folder to `loom build`. Before it bundles, it loads the application module under Bun, judges the folder `skills()` names, and fails on a bad skill. A development build reads the source folder, a distributed bundle carries a copy in `loom-skills/` beside its chunks, and a distributed binary embeds it, so the artifact installs the skills wherever it runs. See [The skills folder](docs/toolchain/build.md#the-skills-folder).
