- Add `mockProcess(fields)` to `@loomcli/testing`, with the types `MockFields`, `MockTerminal`, `MockProcess`, `RecordingStream`, `Program`, `ProgramCall`, and `ProgramAnswer`. It builds a [process handle](docs/core/host.md#the-process-handle) that reads nothing from the process the test runs in: every fact has a sealed default, `stdout` and `stderr` record what a run writes, `exitCode` records what `run()` writes, and its signal source is its own. A test runs an Application with `app.run({ process: mockProcess(...) })` and reads the mock. See the [testing reference](docs/libs/testing.md#mockprocess).
- Add `home` and `tmpdir` defaults to `mockProcess`: the mock's absolute `env.HOME` and `env.TMPDIR`, else `/loom-test/home` and `/loom-test/tmp`, neither of which exists. A supplied `home` or `tmpdir` wins.
- Add `programs` to `mockProcess`, which scripts each child program a run starts through `host.spawn` by its exact command, answering its exit code and output with no program run. A command with no script throws `mockProcess has no program for "<command>". Add a "<command>" entry to programs.` from `spawn`, so the run fails; a script that throws stands for a program that could not start; and a spawn's abort or a `kill` of `SIGHUP`, `SIGINT`, `SIGQUIT`, or `SIGTERM` ends the child with 128 plus the signal's number.
