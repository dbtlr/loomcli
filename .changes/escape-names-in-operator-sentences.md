- Fix core's operator sentences that repeated a declared name or an input source's label without escaping it, so a control character or a bidirectional control in one prints as its `\uXXXX` escape instead of reaching the terminal. Only a name or a label that holds such a character prints differently. Each changed sentence:
  - The subject of a rejected or missing input's line escapes the argument's name, the option's spelling, and the source that filled it. Before, `app: Option "--lev<U+202E>el" (from APP_<U+202E>LEVEL): Use a whole number of 0 or more.` printed the control itself; after, it prints `app: Option "--lev\u202eel" (from APP_\u202eLEVEL): Use a whole number of 0 or more.` The same holds for `Argument "<name>" requires a value. Supply a value for "<name>".` and `Option "<spelling>" (from <source>) is required. Supply a value.`
  - The `-v` line `Ignored option "<spelling>" from <source>: <issue>` escapes the spelling and the source.
  - A sentence that names a Command, such as `Command "<name>" requires a subcommand.`, escapes the name, and the candidates of `Use one of: <names>.` and the commands of `Option "<spelling>" belongs to commands <paths>.` are escaped too. A name core's portable rule accepts prints as before, so only a failure an application builds with such a name prints differently.
