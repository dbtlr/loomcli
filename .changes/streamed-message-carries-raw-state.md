- Fix a streamed message on a lane view core ships laying out its whole text again at every chunk once a finished line held a raw color or hyperlink sequence, a lone carriage return or another terminal control, a pad or no-wrap frame, a header core rejects, a stray close, or a style that names a token the application's theme adds, so the work of a long message grew with the square of its length. The message now carries what such a line leaves open into the lines after it and lays out each finished line a bounded number of times, writing the same bytes as before. It still lays out everything after the last line it had finished once a finished line holds a style naming a token the theme lacks, or a frame header or terminal control string that never ends. Where the rendering policy keeps terminal controls, the message carries every raw SGR command Loom does not track, because each one is written as it is, so a message that sets such a command on every line still lays out text that grows with the square of its length. See [A streamed message](docs/core/output.md#a-streamed-message).
