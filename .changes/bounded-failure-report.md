- Fix `run()` never resolving a failed run whose host stream never calls back on a write. Once a run has a failure to report, each wait core makes on its output, for the writes still in flight or for a write of its report, ends after one second, and core stops waiting without failing or discarding those writes, so the run resolves its code and removes its signal listeners. A run that has not failed still waits for every write to finish, so a slow consumer such as a pager is never cut short. See the [core reference](docs/core.md#output-and-failures).
