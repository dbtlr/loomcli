- Fix two runs that install the same folder at once, such as two terminals running `app skills install`, publishing the folder with files missing. One run's cleanup of leftover staging folders could remove files from the other run's staging folder while that run was still writing it, and the other run then renamed what was left into place and recorded the missing files as written. Cleanup now renames each leftover before it removes it, and so does the removal of a recorded folder, so a folder another run publishes at that moment stays whole. The run whose staging folder was taken, or whose rename into place meets the folder another run just published, fails with `Cannot write /home/me/.claude/skills/notes because another run changed the folder at the same time. Wait for that run to finish, then run the command again.`, and the folder holds its old files or one run's files, each whole, or is gone after an uninstall. A phrasebook can say the new sentence through the `@loomcli/plugins` entry `installation.folderChangedMeanwhile`. The next run that recovers a pending record or writes that folder still removes the staging and retired folders a stopped run left. See [Installation record](../docs/core/installation-record.md#installed-files).
