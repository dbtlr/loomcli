- Fix `format()` advertising `--fields` on a Command whose `json` and `jsonl` views its author declares, where every use of the option failed with exit 2. The formatter now declares `--fields` only on a Command it appended `json`, `jsonl`, or both to, so such a Command's help page, `inspect()` node, and completion list no `--fields` row, and typing it is the unknown-option error. A `fields` option that the Command itself declares there is no longer the hook-collision build error. An Application's or another plugin's `fields` option still collides with the `--fields` the formatter declares on every Command it appended a view to and, hidden, on the root and every other group. A Command with one formatter-appended view keeps `--fields`, and a group keeps its hidden `--fields`. The `format` phrasebook entry `fieldsNeedEncoding` no longer receives an empty view list, so its sentence `Option "--fields" applies only to output the formatter provides, and the formatter provides none here. Remove the option.` is removed. [ADR-0218](../docs/decisions/0218-the-formatter-declares-fields-only-on-a-command-it-appended-a-json-or-jsonl-view-to.md) records the rule.
